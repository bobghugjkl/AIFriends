## 二、前端路由是什么

传统网站中，点击链接 → 浏览器向服务器请求新页面 → 整个页面刷新白屏 → 渲染新 HTML。这个过程慢且有闪烁。

**前端路由（SPA 路由）** 的做法是：点击链接 → JavaScript 拦截点击 → 用 HTML5 History API 修改浏览器地址栏 URL → 只替换页面中 `<RouterView />` 区域的内容。整个过程**没有网络请求**（对应的组件代码已经在首次加载时下载好了），**没有白屏闪烁**，体验像原生 App。

## 三、改动的文件

### 3.1 `frontend/src/router/index.js`——路由配置

```javascript
import { createRouter, createWebHistory } from 'vue-router'
import HomepageIndex from "@/views/homepage/HomepageIndex.vue";
import FriendIndex from "@/views/friend/FriendIndex.vue";
import CreateIndex from "@/views/create/CreateIndex.vue";
import NotFoundIndex from "@/views/error/NotFoundIndex.vue";
import LoginIndex from "@/views/user/account/LoginIndex.vue";
import RegisterIndex from "@/views/user/account/RegisterIndex.vue";
import SpaceIndex from "@/views/user/space/SpaceIndex.vue";
import ProfileIndex from "@/views/user/profile/ProfileIndex.vue";

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/',
      component: HomepageIndex,
      name: 'homepage-index',
    },
    {
      path: '/friend/',
      component: FriendIndex,
      name: 'friend-index',
    },
    {
      path: '/create/',
      component: CreateIndex,
      name: 'create-index',
    },
    {
      path: '/404/',
      component: NotFoundIndex,
      name: '404',
    },
    {
      path: '/user/account/login/',
      component: LoginIndex,
      name: 'user-account-login-index',
    },
    {
      path: '/user/account/register/',
      component: RegisterIndex,
      name: 'user-account-register-index',
    },
    {
      path: '/user/space/:user_id/',
      component: SpaceIndex,
      name: 'user-space-index',
    },
    {
      path: '/user/profile/',
      component: ProfileIndex,
      name: 'user-profile-index',
    },
    {
      path: '/:pathMatch(.*)*',
      component: NotFoundIndex,
      name: 'not-found'
    },
  ],
})
```

**逐项讲解**：

每条路由有三个核心属性：

- `path` —— URL 路径。用户访问这个路径时，对应的组件会渲染。路径以 `/` 结尾表示此路径下的子路径也会匹配
- `component` —— 当 URL 匹配这个 path 时，在 `<RouterView />` 位置渲染的 Vue 组件
- `name` —— 路由的"名字"。用名字跳转比写死 URL 路径更安全——如果以后改路径（比如 `/user/account/login/` → `/login/`），只需改路由配置一处，所有用 `{name: '...'}` 跳转的地方自动跟着变

**动态路由**：
```javascript
{
  path: '/user/space/:user_id/',
  component: SpaceIndex,
  name: 'user-space-index',
}
```
`:user_id` 是一个**路径参数**（动态段）。用户访问 `/user/space/123/` 时，`user_id` 的值就是 `"123"`。在 SpaceIndex 组件里可以通过 `route.params.user_id` 拿到这个值，用于展示不同用户的个人空间。

**通配符路由（404 兜底）**：
```javascript
{
  path: '/:pathMatch(.*)*',
  component: NotFoundIndex,
  name: 'not-found'
},
```
`/:pathMatch(.*)*` 是一个正则匹配——`(.*)` 匹配任意字符，`*` 表示重复任意次。所以这个路由匹配**所有没有被上面路由匹配的 URL**，显示 404 页面。**必须放在 routes 数组最后**，Vue Router 按顺序匹配，放前面会吞掉所有请求。

**注意**：404 有两个路由指向同一个组件：
- `/404/` —— 主动跳转，比如后端返回 404 时前端可以用 `router.push({name: '404'})` 跳过来
- `/:pathMatch(.*)*` —— 兜底，用户输入不存在的 URL 时自动匹配

### 3.2 新建的 8 个页面组件

所有页面组件都是"空壳"，只有一行占位文字：

| 文件路径 | 页面上显示 | 对应路由 |
|---------|-----------|---------|
| `views/homepage/HomepageIndex.vue` | 首页 | `/` |
| `views/friend/FriendIndex.vue` | 好友 | `/friend/` |
| `views/create/CreateIndex.vue` | 创作 | `/create/` |
| `views/error/NotFoundIndex.vue` | 404 | `/404/` |
| `views/user/account/LoginIndex.vue` | 登录 | `/user/account/login/` |
| `views/user/account/RegisterIndex.vue` | 注册 | `/user/account/register/` |
| `views/user/space/SpaceIndex.vue` | 个人空间：{user_id} | `/user/space/:user_id/` |
| `views/user/profile/ProfileIndex.vue` | 编辑资料 | `/user/profile/` |

**`SpaceIndex.vue` 多了一点逻辑**：

```vue
<script setup>
import {useRoute, useRouter} from "vue-router";

const route = useRoute()
</script>

<template>
个人空间：{{ route.params.user_id }}
</template>
```

- `import {useRoute, useRouter} from "vue-router"` —— Vue Router 提供的两个组合式函数（Composables）
- `useRoute()` —— 获取**当前路由**信息（路径、参数、查询字符串等）。返回一个响应式对象，URL 变化时自动更新
- `route.params.user_id` —— 获取路径参数 `:user_id` 的值。比如 URL 是 `/user/space/123/`，这个值就是 `"123"`
- `useRouter()` —— 获取**路由器实例**，用于编程式跳转（如 `router.push('/login/')`）。这个组件 import 了但暂时没用到，后面会用

### 3.3 `App.vue`——把占位文字换成 RouterView

**改之前**：
```html
<NavBar>
  页面内容
</NavBar>
```

**改之后**：
```html
<NavBar>
  <RouterView />
</NavBar>
```

- `<RouterView />` —— Vue Router 的核心组件，根据当前 URL 动态渲染对应的页面组件
- 放在 `<NavBar>` 标签之间，说明 `<RouterView />` 会渲染在 NavBar 的 `<slot></slot>` 位置
- URL 变化 → RouterView 自动切换内容 → 导航栏不变 → 用户感觉"页面没刷新但内容变了"

### 3.4 `NavBar.vue`——把 button 改成 RouterLink

**三处改动**：

#### ① 登录按钮

**改之前**：
```html
<button class="btn btn-ghost text-lg">登录</button>
```

**改之后**：
```html
<RouterLink :to="{name: 'user-account-login-index'}" active-class="btn-active" class="btn btn-ghost text-lg">
  登录
</RouterLink>
```

- `<RouterLink>` —— Vue Router 提供的导航链接组件，渲染为 `<a>` 标签但不会触发浏览器刷新
- `:to="{name: 'user-account-login-index'}"` —— 跳转目标。冒号 `:` 是 Vue 的**动态绑定**语法，`name` 引用了路由配置中的名字。等价于写 `to="/user/account/login/"`
- `active-class="btn-active"` —— 当当前 URL 匹配这个链接的目标路由时，自动添加 `btn-active` class（DaisyUI 里会让按钮高亮）

**为什么用 `:to=` 而不是 `to=`**：不加冒号时 `to` 的值是字符串，只能写死路径。加了冒号后 `to` 的值被当作 JavaScript 表达式求值，可以传入对象 `{name: '...'}` 实现命名路由跳转。

#### ② 侧边栏三个菜单按钮

三个菜单项（首页、好友、创作）从 `<button>` 改成了 `<RouterLink>`，同样的写法：

```html
<RouterLink :to="{name: 'homepage-index'}" active-class="menu-focus" class="...">
  <HomepageIcon />
  <span>首页</span>
</RouterLink>
```

- `active-class="menu-focus"` —— DaisyUI 的 `menu-focus` class，当用户处于该页面时菜单项高亮。比如当前在首页，侧边栏"首页"就亮起来，一眼知道自己在哪个页面

## 四、页面目录结构的设计

```
views/
├── homepage/HomepageIndex.vue   # 首页
├── friend/FriendIndex.vue       # 好友页
├── create/CreateIndex.vue       # 创作页
├── error/NotFoundIndex.vue      # 404
└── user/
    ├── account/
    │   ├── LoginIndex.vue       # 登录页
    │   └── RegisterIndex.vue    # 注册页
    ├── profile/ProfileIndex.vue # 编辑资料
    └── space/SpaceIndex.vue     # 个人空间
```

**为什么按功能模块分目录**：`user/account/` 下放账号相关的页面，`user/profile/` 下放资料相关的页面。这是一种前端约定，叫"功能分组"——同一个业务的页面放在一起，方便查找和维护，不会出现几百个文件全堆在 `views/` 根目录的噩梦。
