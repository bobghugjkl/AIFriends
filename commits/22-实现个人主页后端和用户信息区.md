## 二、后端：`GetListCharacterView`

**文件**：`backend/web/views/create/character/get_list.py`（新文件）

```python
class GetListCharacterView(APIView):
    def get(self, request):
        items_count = int(request.query_params.get('items_count'))
        user_id = int(request.query_params.get('user_id'))
        user = User.objects.get(id=user_id)
        user_profile = UserProfile.objects.get(user=user)
        characters_raw = Character.objects.filter(
            author=user_profile
        ).order_by('-id')[items_count: items_count + 20]
        characters = []
        for character in characters_raw:
            author = character.author
            characters.append({
                'id': character.id,
                'name': character.name,
                'profile': character.profile,
                'photo': character.photo.url,
                'background_image': character.background_image.url,
                'author': {
                    'user_id': author.user_id,
                    'username': author.user.username,
                    'photo': author.photo.url,
                }
            })
```

**核心逻辑——分页查询**：

- `items_count` —— 前端传"我已经加载了多少条"，后端从这个位置开始返回新数据。这叫**基于偏移量（offset）的分页**
- `Character.objects.filter(author=user_profile).order_by('-id')[items_count: items_count + 20]` —— 每次返回 20 条。Django ORM 的切片语法 `[start:end]` 会被翻译为 SQL 的 `LIMIT 20 OFFSET items_count`
- **同时返回了角色的作者信息**（`author` 嵌套对象），因为角色卡片上需要显示"谁创建的"

## 三、前端：无限滚动加载

**文件**：`SpaceIndex.vue`

```javascript
const sentinelRef = useTemplateRef('sentinel-ref')
let observer = null

onMounted(async () => {
  await loadMore()  // 先加载第一批

  observer = new IntersectionObserver(
    entries => {
      entries.forEach(entry => {
        if (entry.isIntersecting) {
          loadMore()  // 哨兵元素进入视口 → 加载更多
        }
      })
    },
    {root: null, rootMargin: '2px', threshold: 0}
  )
  observer.observe(sentinelRef.value)
})
```

**`IntersectionObserver` 是什么**：浏览器原生 API，用于监听某个元素是否进入了视口（viewport）。它比监听 scroll 事件效率高得多——scroll 事件每秒触发数百次，IntersectionObserver 只在交叉状态变化时触发一次。

**参数解释**：
- `root: null` —— 以浏览器视口为观察区域
- `rootMargin: '2px'` —— 视口外围扩 2px，提前触发
- `threshold: 0` —— 哨兵元素的 0% 进入视口时就触发

**哨兵元素**：
```html
<div ref="sentinel-ref" class="h-2 mt-8 w-100 bg-red-500"></div>
```
一个宽 400px、高 8px 的红色条（用于调试可见）。放在角色列表底部。当用户滚动到页面底部，这个元素进入视口，触发 `loadMore()`。红色背景在后续提交中会被去掉。

**`loadMore` 函数**：
```javascript
async function loadMore() {
  if (isLoading.value || !hasCharacters.value) return  // 防重复加载
  isLoading.value = true

  const res = await api.get('/api/create/character/get_list/', {
    params: {
      items_count: characters.value.length,  // 当前已加载数
      user_id: route.params.user_id,
    }
  })

  // 加载完后检查：如果页面还不够一屏，继续加载
  if (newCharacters.length > 0) {
    characters.value.push(...newCharacters)
    await nextTick()
    if (checkSentinelVisible()) {   // 哨兵还在视野内 = 内容不够 → 继续加载
      await loadMore()
    }
  }
}
```

**`checkSentinelVisible` 的递归加载逻辑**：在大屏幕上，20 条角色卡片可能还不够撑满一屏。加载后检查哨兵是否仍然在视野内——如果在，说明内容不够，递归再加载一批，直到内容超过一屏。
