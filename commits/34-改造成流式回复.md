## 二、什么是 SSE

**SSE（Server-Sent Events）** 是 HTTP 协议的一种使用方式：服务器不一次性返回全部内容，而是保持连接打开，通过 `text/event-stream` 格式不断推送数据。每个数据块格式为 `data: ...\n\n`，结束时发 `data: [DONE]\n\n`。

**SSE vs WebSocket**：
- SSE：单向（服务器→客户端），基于 HTTP，简单，浏览器原生支持（`EventSource` API）
- WebSocket：双向，基于独立协议，更复杂，适合需要客户端频繁发消息的场景
- 聊天场景中客户端只需要"发一条消息"+"接收流式回复"，SSE 足够

## 三、后端改动：从 `invoke` 到 `stream`

**文件**：`chat.py`

```python
from django.http import StreamingHttpResponse

class SSERenderer(BaseRenderer):
    media_type = 'text/event-stream'
    format = 'txt'
    def render(self, data, accepted_media_type=None, renderer_context=None):
        return data

class MessageChatView(APIView):
    renderer_classes = [SSERenderer]  # 覆盖DRF默认JSON渲染器
```

**`SSERenderer`**：DRF 默认把响应序列化为 JSON。SSE 需要原始的文本数据不被处理，所以自定义渲染器——直接返回原始字符串不加工。

**流式生成器函数**：

```python
def event_stream():
    full_usage = {}
    for msg, metadata in app.stream(inputs, stream_mode="messages"):
        if isinstance(msg, BaseMessageChunk):
            if msg.content:
                yield f'data: {json.dumps({"content": msg.content}, ensure_ascii=False)}\n\n'
            if hasattr(msg, 'usage_metadata') and msg.usage_metadata:
                full_usage = msg.usage_metadata
    yield 'data: [DONE]\n\n'
    print(full_usage)
```

**逐行讲解**：

- `def event_stream():` —— Python **生成器函数**（generator）。用 `yield` 而不是 `return`，每次 yield 向客户端推送一部分数据
- `app.stream(inputs, stream_mode="messages")` —— **流式调用**而不是 `invoke`。AI 生成一个字就 yield 一个字（`BaseMessageChunk`），不是生成完才返回完整 `AIMessage`
- `stream_mode="messages"` —— LangGraph 的流模式，输出消息级别的 token 流
- `for msg, metadata in app.stream(...)` —— 每次迭代得到 AI 新生成的一个 token 块 + 元数据
- `isinstance(msg, BaseMessageChunk)` —— 过滤掉不是消息内容的块（可能是工具调用等）
- `yield f'data: {json.dumps({"content": msg.content}, ensure_ascii=False)}\n\n'` —— SSE 格式。`data: <JSON>\n\n` 是标准格式（两个换行表示一个事件结束）。`ensure_ascii=False` 让中文字符正常显示而不是 `\uXXXX`
- `yield 'data: [DONE]\n\n'` —— 结束信号。前端收到 `[DONE]` 知道流结束了
- `hasattr(msg, 'usage_metadata')` —— DeepSeek 流式模式下，最后一条消息会附带 token 消耗量

**Django StreamingHttpResponse**：

```python
response = StreamingHttpResponse(event_stream(), content_type='text/event-stream')
response['Cache-Control'] = 'no-cache'  # 不允许缓存
return response
```

`StreamingHttpResponse` 接收一个生成器，边生成边发送。Django 不会等生成器结束才返回——每 yield 一次，Django 就把数据写入 TCP 连接发送到客户端。

## 五、前端：`streamApi.js`——流式请求工具

**引入**：`@microsoft/fetch-event-source`——微软的库，封装了浏览器的 `fetch` 为 SSE 客户端。比浏览器原生的 `EventSource` 好在：支持 POST 请求、支持自定义 headers、更好的错误处理。

```javascript
import { fetchEventSource } from '@microsoft/fetch-event-source';

export default async function streamApi(url, options = {}) {
    return await fetchEventSource(BASE_URL + url, {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'Authorization': `Bearer ${userStore.accessToken}`,
        },
        body: JSON.stringify(options.body || {}),
        openWhenHidden: true,  // 页面在后台也能继续接收

        async onopen(response) {
            if (response.status === 401) {
                // Token过期，先用Axios拦截器刷新
                await api.post('/api/user/account/refresh_token/', {});
                throw new Error("TOKEN_REFRESHED");  // 在onerror中重试
            }
        },

        onmessage(msg) {
            if (msg.data === '[DONE]') {
                options.onmessage('', true);    // isDone=true
                return
            }
            const json = JSON.parse(msg.data);
            options.onmessage(json, false);     // isDone=false
        },

        onerror(err) {
            if (err.message === "TOKEN_REFRESHED") {
                return startFetch();    // 递归重试（Token已刷新）
            }
            options.onerror?.(err);
            throw err;
        },
    });
}
```

**`startFetch()` 递归重试**：`onerror` 中检测到 TOKEN_REFRESHED 错误 → 调用 `startFetch()` 重新发起请求。由于之前在 `onopen` 中已经刷新了 Token，第二次请求能正常通过。

## 六、`InputField.vue`——对接流式 API

```javascript
async function handleSend() {
  const content = message.value.trim()
  if (!content) return
  message.value = ''     // 清空输入框

  await streamApi('/api/friend/message/chat/', {
    body: {
      friend_id: props.friendId,
      message: content,
    },
    onmessage(data, isDone) {
      if (isDone) {
        isProcessing = false
      } else if (data.content) {
        console.log(data.content)    // 暂时打印到控制台，还没显示到界面
      }
    },
  })
}
```

**`isProcessing` 防重复发送**：AI 回复期间 `isProcessing = true`，防止用户狂点发送按钮。

**`defineExpose({focus})`**：暴露 `focus()` 方法给父组件，对话框打开后自动聚焦输入框。

## 七、总结

| 改动 | 说明 |
|------|------|
| `SSERenderer` | DRF 自定义渲染器，输出原始文本不加工 |
| `event_stream()` 生成器 | Python yield 语法实现流式推送 |
| `app.stream()` 替代 `app.invoke()` | LangGraph 流式模式 |
| `StreamingHttpResponse` | Django 流式响应，不等待全部生成 |
| `streamApi.js`（新） | 前端 SSE 客户端，支持 POST + 401自动刷新重试 |
| `@microsoft/fetch-event-source` | 比原生 EventSource 更强大的 SSE 库 |
