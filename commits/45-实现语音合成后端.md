## 二、架构改造：生成器 → 多线程 + 消息队列

**改之前**：
```
SSE 流 → yield 文字 → 前端接收
```

**改之后**：
```
LangGraph 流 → WebSocket → TTS服务 → 音频
             ↘ 消息队列 → SSE 流 → 文字 + 音频 → 前端
```

### 核心数据结构：`Queue`（消息队列）

```python
from queue import Queue

mq = Queue()
thread = threading.Thread(target=self.work, args=(app, inputs, mq))
thread.start()
```

- `Queue` —— Python 标准库的**线程安全**队列。`work` 线程往队列写数据（文字+音频），主线程从队列读数据并 yield 给 SSE
- 启动一个**独立线程**运行异步事件循环（WebSocket 连接 TTS 服务）

### `work` → `run_tts_tasks`（异步线程）

```python
def work(self, app, inputs, mq):
    try:
        asyncio.run(self.run_tts_tasks(app, inputs, mq))
    finally:
        mq.put_nowait(None)    # None 作为"结束"信号
```

### `run_tts_tasks`（TTS WebSocket 流程）

```python
async def run_tts_tasks(self, app, inputs, mq):
    # 1. 连接 TTS WebSocket
    async with websockets.connect(wss_url, ...) as ws:
        # 2. 发送 run-task（model="cosyvoice-v3-flash"）
        # 3. 等待 task-started
        # 4. 并发运行两个协程：
        await asyncio.gather(
            self.tts_sender(app, inputs, mq, ws, task_id),  # 流式发文本
            self.tts_receiver(mq, ws),                       # 流式收音频
        )
```

### `tts_sender`——边生成文字边发 TTS

```python
async def tts_sender(self, app, inputs, mq, ws, task_id):
    async for msg, metadata in app.astream(inputs, stream_mode="messages"):
        if msg.content:
            # 文字发给 TTS 服务合成语音
            await ws.send(json.dumps({
                "header": {"action": "continue-task", "task_id": task_id},
                "payload": {"input": {"text": msg.content}}
            }))
            mq.put_nowait({'content': msg.content})  #同时发给SSE显示文字
```

**`app.astream` vs `app.stream`**：`astream` 是异步生成器（async generator），能在 WebSocket 协程中 await；`stream` 是同步的，不能在异步上下文中直接使用。

### `tts_receiver`——接收合成音频

```python
async def tts_receiver(self, mq, ws):
    async for msg in ws:
        if isinstance(msg, bytes):
            audio = base64.b64encode(msg).decode('utf-8')
            mq.put_nowait({'audio': audio})          # Base64编码后放入队列
        else:
            event = json.loads(msg)['header']['event']
            if event in ['task-finished', 'task-failed']:
                break
```

收到的音频是二进制 → Base64 转字符串 → 放入消息队列 → 主线程通过 SSE 推给前端。

### `event_stream`——主线程消费队列

```python
def event_stream(self, app, inputs, friend, message):
    mq = Queue()
    thread = threading.Thread(target=self.work, args=(app, inputs, mq))
    thread.start()

    while True:
        msg = mq.get()              # 阻塞等待
        if not msg:                 # None = 结束信号
            break
        if msg.get('content'):
            yield f'data: {json.dumps({"content": msg["content"]})}\n\n'
        if msg.get('audio'):
            yield f'data: {json.dumps({"audio": msg["audio"]})}\n\n'
```

**为什么用多线程**：Django 是同步框架，`StreamingHttpResponse` 的生成器必须同步。但 TTS 需要 WebSocket（异步）。解决方案：异步线程跑 WebSocket → 消息队列 → 主线程读队列 → yield。

## 三、总结

| 改动 | 说明 |
|------|------|
| `Queue` + `Thread` | 同步线程和异步线程通过消息队列通信 |
| `tts_sender` | 流式发文本给 TTS 服务 |
| `tts_receiver` | 接收音频 → Base64 → 放入队列 |
| `cosyvoice-v3-flash` | 阿里云百炼的流式 TTS 模型 |
| SSE 新增 `audio` 字段 | 每条 SSE 事件可能包含文字或音频 |
