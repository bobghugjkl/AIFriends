## 二、使用了什么技术

| 技术 | 用途 |
|------|------|
| Django ORM (`models.Model`) | 对象关系映射，用 Python 类定义数据库表结构，无需手写 SQL |
| `OneToOneField` | 一对一外键，扩展 Django 内置 `User` 模型，实现 Profile 模式 |
| `ImageField` | 图片字段，数据库存文件路径，实际文件存磁盘 `MEDIA_ROOT` 目录 |
| `DateTimeField` + `timezone.now` | 带时区感知的时间戳字段，记录创建和更新时间 |
| Django Migration 系统 | 自动从模型定义生成建表脚本 (`makemigrations`)，支持版本控制和数据库无关性 |
| UUID 随机文件名 | `uuid.uuid4().hex[:10]` 生成唯一文件名，防止用户上传文件重名覆盖 |
| `admin.register` 装饰器 | 将模型注册到 Django 管理后台，`raw_id_fields` 优化外键搜索性能 |

## 三、整体架构 / 数据流

### User 模型扩展模式 (Profile Pattern)

```
Django 内置 auth_user 表                    web_userprofile 表
（由 django.contrib.auth 自动创建）          （本次提交创建）
┌──────────────────────┐                 ┌──────────────────────────┐
│  id (PK, 自增)       │←──OneToOneField──│  id (PK, 自增)           │
│  username (唯一)      │   一对一关系     │  user_id (FK → auth_user)│
│  password (哈希加密)  │                 │  photo (图片路径)         │
│  email                │                 │  profile (个人简介文本)   │
│  ...                  │                 │  create_time             │
└──────────────────────┘                 │  update_time             │
        │                                └──────────────────────────┘
        │ 每个 User 有且只有一个 UserProfile
        │ 每个 UserProfile 属于一个 User
        ▼
    删除 User 时 → CASCADE → 自动删除关联的 UserProfile
```

### 文件上传流程

```
用户上传头像文件
       │
       ▼
ImageField(upload_to=photo_upload_to)  ← Django 自动调用回调
       │
       ▼
photo_upload_to(instance, filename):

       ▼

```

## 四、数据库模型（表定义）

### 2.1 把 `models.py` 从"文件"重构为"包"

**删除**：`backend/web/models.py`（原来是单文件，里面只有注释）
**新建**：`backend/web/models/__init__.py`（空的） + `backend/web/models/user.py`（真正放模型的文件）

**为什么把一个文件变成目录**：随着项目增长，所有模型堆在一个 `models.py` 里会变成几千行的巨无霸文件。Django 允许把 `models` 拆成多文件——创建 `models/` 目录，每个文件放一类模型（`user.py` 放用户相关、`friend.py` 好友相关等）。`__init__.py` 让 Python 把这个目录当成包（package），可以 `from web.models.user import UserProfile`。

### 2.2 `backend/web/models/user.py`——用户资料模型

```python
import uuid

from django.contrib.auth.models import User
from django.db import models
from django.utils.timezone import now, localtime


def photo_upload_to(instance, filename):
    ext = filename.split('.')[-1]
    filename = f'{uuid.uuid4().hex[:10]}.{ext}'
    return f'user/photos/{instance.user_id}_{filename}'


class UserProfile(models.Model):
    user = models.OneToOneField(User, on_delete=models.CASCADE)
    photo = models.ImageField(default='user/photos/default.png', upload_to=photo_upload_to)
    profile = models.TextField(default='谢谢你的关注', max_length=500)
    create_time = models.DateTimeField(default=now)
    update_time = models.DateTimeField(default=now)

    def __str__(self):
        return f'{self.user.username} - {localtime(self.create_time).strftime('%Y-%m-%d %H:%M:%S')}'
```

---

#### 先讲函数 `photo_upload_to`

```python
def photo_upload_to(instance, filename):
    ext = filename.split('.')[-1]
    filename = f'{uuid.uuid4().hex[:10]}.{ext}'
    return f'user/photos/{instance.user_id}_{filename}'
```

这是 Django 的**上传路径回调函数**，Django 在保存图片时会自动调用它来决定文件存到哪里：

- `instance` —— 当前正在保存的 `UserProfile` 对象。如果用户还没保存到数据库，`instance.user_id` 是 `None`（因为还没分配 id）
- `filename` —— 用户上传的原始文件名，比如 `"我的头像.png"`
- `ext = filename.split('.')[-1]` —— 按 `.` 分割文件名，取最后一段作为扩展名。`"我的头像.png"` → `['我的头像', 'png']` → `ext = 'png'`
- `uuid.uuid4().hex[:10]` —— 生成一个随机唯一字符串的前 10 个字符。`UUID4` 是随机生成的，全世界独一无二，用作文件名防止**文件名冲突**（两个人上传 `1.png` 不会互相覆盖）
- `f'user/photos/{instance.user_id}_{filename}'` —— 最终路径如 `user/photos/1_a1b2c3d4e5.png`。目录按用户 id 组织，方便管理

#### 再讲模型类 `UserProfile`

```python
class UserProfile(models.Model):
```

继承 `models.Model`，Django 会自动为这个类创建一张数据库表（名叫 `web_userprofile`——应用名 + 下划线 + 类名小写）。

```python
    user = models.OneToOneField(User, on_delete=models.CASCADE)
```

**`OneToOneField`**——一对一外键。每个 `UserProfile` 必须且只能关联一个 Django 内置的 `User` 对象；每个 `User` 最多只能有一个 `UserProfile`。

**为什么不用 `ForeignKey`**：`ForeignKey` 是一对多（一个用户可以有多个资料），不合适。`OneToOneField` 严格保证了一对一关系。

**为什么要把 User 和 UserProfile 分开**：Django 内置的 `User` 表已经有 `username`、`password`、`email` 等基础字段了。如果我们想加头像、个人简介等字段，最好的做法不是改 User 表（改 Django 源码不现实），而是创建一个 `UserProfile` 表**扩展** User。这是 Django 生态的标准做法——"Profile 模式"。

`on_delete=models.CASCADE` 的意思是：当关联的 `User` 被删除时，这个 `UserProfile` 也自动删除（级联删除）。如果不设，数据库外键约束会导致删除 User 时因为被 UserProfile 引用而报错。

```python
    photo = models.ImageField(default='user/photos/default.png', upload_to=photo_upload_to)
```

**`ImageField`**——图片字段。在数据库里存的是**文件路径字符串**（不是图片本身），图片文件存在磁盘的 `MEDIA_ROOT/user/photos/` 目录下。
- `default='user/photos/default.png'` —— 新用户还没上传头像时用默认图片
- `upload_to=photo_upload_to` —— 上传文件时调用上面的函数确定存储路径。`upload_to` **不传函数名后面的括号**，表示传入的是函数本身而不是调用结果，Django 会在需要时才调用它

```python
    profile = models.TextField(default='谢谢你的关注', max_length=500)
```

个人简介文本，最长 500 字。默认值是 `'谢谢你的关注'`——新用户注册后不用自己填也有展示内容。

```python
    create_time = models.DateTimeField(default=now)
    update_time = models.DateTimeField(default=now)
```

创建时间和更新时间。`default=now` 用的是 `django.utils.timezone.now`（带时区感知），而不是 Python 的 `datetime.now`（不带时区）。

```python
    def __str__(self):
        return f'{self.user.username} - {localtime(self.create_time).strftime('%Y-%m-%d %H:%M:%S')}'
```

`__str__` 是 Python 的"转字符串"魔术方法。当 Django Admin 或其他地方需要把这个对象显示为字符串时（如下拉菜单、面包屑等），会调用这个方法。这里返回格式如 `"zhangsan - 2026-01-27 20:57:41"`。

### 2.3 迁移文件 `backend/web/migrations/0001_initial.py`

```python
# Generated by Django 6.0.1 on 2026-01-27 12:54

import django.db.models.deletion
import django.utils.timezone
import web.models.user
from django.conf import settings
from django.db import migrations, models


class Migration(migrations.Migration):

    initial = True

    dependencies = [
        migrations.swappable_dependency(settings.AUTH_USER_MODEL),
    ]

    operations = [
        migrations.CreateModel(
            name='UserProfile',
            fields=[
                ('id', models.BigAutoField(auto_created=True, primary_key=True, serialize=False, verbose_name='ID')),
                ('photo', models.ImageField(default='user/photos/default.png', upload_to=web.models.user.photo_upload_to)),
                ('profile', models.TextField(default='谢谢你的关注', max_length=500)),
                ('create_time', models.DateTimeField(default=django.utils.timezone.now)),
                ('update_time', models.DateTimeField(default=django.utils.timezone.now)),
                ('user', models.OneToOneField(on_delete=django.db.models.deletion.CASCADE, to=settings.AUTH_USER_MODEL)),
            ],
        ),
    ]
```

**迁移文件是什么**：Django ORM 的一大特性。你在 `models.py` 里用 Python 代码定义表结构，然后运行 `python manage.py makemigrations`，Django 会自动生成这个迁移文件（一个描述"如何创建这张表"的 Python 脚本）。再运行 `python manage.py migrate`，Django 执行这个迁移文件，在数据库里真正创建表。

**迁移文件的好处**：
- 不用手写 SQL——Django 替你生成 `CREATE TABLE ...` 语句
- 数据库无关——同一套 Python 模型定义，换成 MySQL/PostgreSQL/SQLite 自动生成对应的 SQL
- 版本控制——迁移文件提交到 Git，其他开发者拉下来执行 `migrate` 后数据库结构完全一致

**`initial = True`** —— 标记这是该应用的第一个迁移。Django 用来判断迁移链的起点。

**`dependencies`** —— 这个迁移依赖谁。`swappable_dependency(settings.AUTH_USER_MODEL)` 表示依赖 Django 内置的 User 表先创建好（因为 `UserProfile` 有外键指向 User 表）。

**`operations`** —— 迁移执行的 SQL 操作。`CreateModel` = 创建一张表。`BigAutoField` 是 Django 默认的自增主键（id 字段）。

### 2.4 `backend/web/admin.py`——注册后台管理

```python
from django.contrib import admin
from web.models.user import UserProfile


@admin.register(UserProfile)
class UserProfileAdmin(admin.ModelAdmin):
    raw_id_fields = ('user',)
```

**逐行讲解：**

- `@admin.register(UserProfile)` —— Python **装饰器**语法。等价于 `admin.site.register(UserProfile, UserProfileAdmin)`。装饰器是一种语法糖，`@admin.register(UserProfile)` 写在类定义前，等价于在类定义完后调用 `admin.site.register(UserProfile, UserProfileAdmin)`
- `class UserProfileAdmin(admin.ModelAdmin)` —— 自定义这个模型在后台管理的显示方式。继承 `ModelAdmin` 才能改配置
- `raw_id_fields = ('user',)` —— 值是一个**元组**（tuple），不是列表。`('user',)` 末尾的逗号是必须的——Python 中 `('user')` 会被解析为括号包裹的字符串而不是元组，`('user',)` 才表示"只包含一个元素的元组"

**`raw_id_fields` 的作用**：`user` 是一个外键字段。Django Admin 默认会把外键渲染成一个 `<select>` 下拉框，列出所有 User。当 User 数量很多时（几百上千），下拉框会导致页面加载巨慢。`raw_id_fields` 把这个下拉框改成一个"弹窗搜索"组件——点击弹出一个窗口，可以搜索用户名、过滤、翻页。逗号后面有个中文注释 `#逗号千万不要删！！！！`，说明作者可能因为删掉逗号碰到过 bug。

## 五、总结

| 概念 | 说明 |
|------|------|
| `models.Model` | Django 的基类，继承它创建数据库表 |
| `OneToOneField` | 一对一外键，用在一个 User 扩展一个 UserProfile 的场景 |
| `ImageField` + `upload_to` | 图片字段，回调函数决定文件存储路径 |
| `ForeignKey.on_delete=CASCADE` | 级联删除——关联的对象被删时本条自动删除 |
| Migration 迁移文件 | Django 自动生成的建表脚本，版本控制 + 数据库无关 |
| `raw_id_fields` | Admin 后台外键字段的优化显示（弹窗搜索而非下拉框） |
| `__str__` | 对象的字符串表示，Admin 和其他地方显示时调用 |
