## 一、这次提交做了什么

实现了**长期记忆提取**——每次聊天结束后，用一个独立的 LLM 调用分析最近对话，提取要点存到 `Friend.memory` 字段。下次聊天时，长期记忆会被注入到系统提示词中，让 AI 能在多轮对话限制（最近 10 轮）之外记住更早的关键信息。

---

## 二、为什么需要长期记忆

`add_recent_messages` 只能取最近 10 轮对话（约 20 条消息）。如果用户和 AI 聊了 100 轮，再问"还记得我最开始说的那个事吗"——AI 看不到，因为那不在最近 10 轮里。

**长期记忆的思路**：不把 100 轮全发给 AI（太贵太慢），而是让另一个 AI 去"读历史、写摘要"，把关键信息浓缩成一段文字（`memory`），每次聊天都带这段摘要。AI 看到记忆就知道用户之前聊过什么重要内容。

## 四、`update_memory.py`——记忆更新逻辑

```python
def create_system_message():
    system_prompts = SystemPrompt.objects.filter(title='记忆').order_by('order_number')
    prompt = ''
    for sp in system_prompts:
        prompt += sp.prompt
    return SystemMessage(prompt)

def create_human_message(friend):
    prompt = f'【原始记忆】\n{friend.memory}\n'
    prompt += f'【最近对话】\n'
    messages = list(Message.objects.filter(friend=friend).order_by('-id')[:10])
    messages.reverse()
    for m in messages:
        prompt += f'user: {m.user_message}\n'
        prompt += f'ai: {m.output}\n'
    return HumanMessage(prompt)
```

**两个 message 拼起来**：
1. **`SystemMessage`**——`title='记忆'` 的系统提示词（告诉 AI"你的任务是从对话中提取关键信息"）
2. **`HumanMessage`**——包含当前的旧记忆 + 最近 10 轮对话。AI 的任务是基于旧记忆和新对话，输出更新后的记忆摘要

**为什么取最近 10 条消息而不是全部**：全部消息可能成百上千条，全塞给 AI 会超出 token 上限且浪费钱。

```python
def update_memory(friend):
    app = MemoryGraph.create_app()
    inputs = {'messages': [
        create_system_message(),
        create_human_message(friend),
    ]}
    res = app.invoke(inputs)
    friend.memory = res['messages'][-1].content   # AI 输出的摘要存到数据库
    friend.update_time = now()
    friend.save()
```

## 七、总结

| 组件 | 作用 |
|------|------|
| `MemoryGraph` | 独立的 LangGraph 工作流，专门做记忆提取 |
| `update_memory` | 组装 prompt → 调 LLM → 存 AI 输出的摘要 |
| `title='记忆'` 的 SystemPrompt | 记忆提取的"规则"（管理员后台配置） |
| `friend.memory` | Friend 表中的存储字段 |
| `% 1 == 0` | 触发频率——每次聊天后更新（可调） |

**整个记忆循环**：聊天 → AI 对话 → 消息入库 → `update_memory` → AI 读取旧记忆+新对话 → 输出新记忆 → 存入 `friend.memory` → 下次聊天出现在系统提示词中。
