## 二、Pinia Store——`frontend/src/stores/user.js`

```javascript
import {defineStore} from "pinia";
import {ref} from "vue";

export const useUserStore = defineStore('user', () => {
    const id = ref(1)
    const username = ref('yxc')
    const photo = ref('http://127.0.0.1:8000/media/user/photos/default.png')
    const profile = ref('111')
    const accessToken = ref('111')

    function isLogin() {
        return !!accessToken.value  // 必须带value!!!!!!!!!
    }

    function setAccessToken(token) {
        accessToken.value = token
    }

    function setUserInfo(data) {
        id.value = data.user_id
        username.value = data.username
        photo.value = data.photo
        profile.value = data.profile
    }

    function logout() {
        id.value = 0
        username.value = ''
        photo.value = ''
        profile.value = ''
        accessToken.value = ''
    }

    return {
        id, username, photo, profile, accessToken,
        isLogin, setAccessToken, setUserInfo, logout,
    }
})
```

**逐行讲解：**

- `export const useUserStore = defineStore('user', () => {...})` —— 定义一个 Pinia Store。第一个参数 `'user'` 是 Store 的名字，第二个参数是一个返回对象的函数。Pinia 采用**组合式 API**（Composition API）风格，写法和 Vue 组件的 `<script setup>` 几乎一样

- `const id = ref(1)` —— 截至目前，这些值都是**硬编码的模拟数据**（`id=1`、`username='yxc'` 等），还没有实现真正的登录数据存储。这些是占位用的，前端页面在对接 API 前需要先用模拟数据跑通 UI 逻辑

- `function isLogin() { return !!accessToken.value }` —— 判断是否已登录。`!!` 是**双重否定**操作符，把任何值转成布尔值：
  - `accessToken.value` 为 `'111'`（非空字符串） → `!'111'` = `false` → `!!'111'` = `true`
  - `accessToken.value` 为 `''`（空字符串） → `!''` = `true` → `!!''` = `false`
  注释强调 `# 必须带value!!!!!!!!!`——在 Pinia 的 setup 函数里，ref 变量的值必须通过 `.value` 访问，忘了加会返回 `RefImpl` 对象，`!!RefImpl` 永远是 `true`

- `function setUserInfo(data)` —— 接收后端返回的用户信息对象，更新 Store 中的状态。后续登录成功后调用这个函数保存用户数据

- `function logout()` —— 清空所有用户数据。id 设为 0，access token 清空，`isLogin()` 就会返回 `false`

- `return { ... }` —— 重要！`return` 中列出的属性和方法才会暴露给外部使用。注释 `# 千万不要忘了！！！！` 说明作者可能在这踩过坑——加了 ref 但忘了 return，组件里 import 后死活拿不到值

**Store 是什么以及为什么要用它**：多个组件（导航栏、下拉菜单、各个页面）都需要知道"用户是谁、登录没"。如果不用 Store，只能在组件间通过 props 层层传递，或者每个组件都发请求问后端"我是谁"。Store 提供了一个**全局共享状态**——登录成功后更新 Store，所有用到 Store 的组件都自动更新。

## 三、`UserMenu.vue`——下拉菜单组件

```vue
<script setup>
import {useUserStore} from "@/stores/user.js";
import UserSpaceIndex from "@/components/navbar/icons/UserSpaceIndex.vue";
import UserProfileIcon from "@/components/navbar/icons/UserProfileIcon.vue";
import UserLogoutIcon from "@/components/navbar/icons/UserLogoutIcon.vue";

const user = useUserStore()

function closeMenu() {
  const element = document.activeElement
  if (element && element instanceof HTMLElement) element.blur()
}
</script>

<template>
  <div class="dropdown dropdown-end">
    <div tabindex="0" role="button" class="avatar btn btn-circle w-8 h-8 mr-6">
      <div class="w-8 rounded-full">
        <img :src="user.photo" alt="">
      </div>
    </div>
    <ul tabindex="-1" class="dropdown-content menu bg-base-100 rounded-box z-1 w-52 p-2 shadow-lg">
      <li>
        <RouterLink @click="closeMenu" :to="{name: 'user-space-index', params: {user_id: user.id}}">
          <div class="avatar">
            <div class="w-10 rounded-full">
              <img :src="user.photo" alt="">
            </div>
          </div>
          <span class="text-base font-bold line-clamp-1">{{ user.username }}</span>
        </RouterLink>
      </li>
      <li>
        <RouterLink @click="closeMenu" :to="{name: 'user-space-index', params: {user_id: user.id}}" class="text-sm font-bold py-3">
          <UserSpaceIndex />
          个人空间
        </RouterLink>
      </li>
      <li>
        <RouterLink @click="closeMenu" :to="{name: 'user-profile-index'}" class="text-sm font-bold py-3">
          <UserProfileIcon />
          编辑资料
        </RouterLink>
      </li>
      <li></li>
      <li>
        <a @click="closeMenu" class="text-sm font-bold py-3">
          <UserLogoutIcon />
          退出登录
        </a>
      </li>
    </ul>
  </div>
</template>
```

**逐段讲解：**

### `closeMenu()` 函数

```javascript
function closeMenu() {
  const element = document.activeElement
  if (element && element instanceof HTMLElement) element.blur()
}
```

- `document.activeElement` —— 浏览器原生 API，返回**当前获得焦点的 DOM 元素**。点击菜单项时，焦点在当前按钮上
- `element.blur()` —— 让元素**失去焦点**。对于 DaisyUI 的 dropdown，下拉菜单通过 CSS `:focus` 伪类控制开关——trigger 获得焦点 → 菜单出现；失去焦点 → 菜单消失。所以 `.blur()` 就能关闭菜单
- `instanceof HTMLElement` —— 类型检查。确保 `activeElement` 是 HTML 元素（有 `blur` 方法），因为 SVG 元素理论上也可能获得焦点但没有 `blur`

### DaisyUI Dropdown 的 HTML 结构

```html
<div class="dropdown dropdown-end">
  <div tabindex="0" role="button">  ← trigger：点击/聚焦后显示菜单
    <!-- 头像 -->
  </div>
  <ul tabindex="-1" class="dropdown-content menu ...">  ← 下拉菜单内容
    <!-- 菜单项 -->
  </ul>
</div>
```

DaisyUI 的 dropdown 是**纯 CSS 实现**，不需要 JavaScript。原理：
- `dropdown` 容器 + `tabindex="0"` 的子元素 = 可聚焦的触发器
- 当触发器获得焦点时，CSS 规则 `.dropdown:focus-within .dropdown-content` 把菜单显示出来
- `dropdown-end` = 菜单右对齐（不设置则默认左对齐）
- `tabindex="-1"` = 菜单内容可以通过 JS 聚焦但不会被 Tab 键遍历到

### 菜单项详解

**第一项——用户头像+名称**：
```html
<RouterLink :to="{name: 'user-space-index', params: {user_id: user.id}}">
  <div class="avatar">
    <div class="w-10 rounded-full">
      <img :src="user.photo" alt="">
    </div>
  </div>
  <span class="text-base font-bold line-clamp-1">{{ user.username }}</span>
</RouterLink>
```
- `params: {user_id: user.id}` —— 动态路由参数。跳转到 `/user/space/:user_id/`，传入当前用户的 id。`user.id` 来自 Store
- `line-clamp-1` —— Tailwind 的文本截断 class，超出宽度显示省略号（`...`）
- `{{ user.username }}` —— 双花括号是 Vue 的**文本插值**，将变量值渲染为文本

**第二项——个人空间**：跳转目标同上，带小房子图标

**第三项——编辑资料**：跳转到 `/user/profile/`

**第四项——`<li></li>`**：一个空的列表项，作用是在菜单中生成一条分隔线。DaisyUI 的 `menu` 中，空的 `<li>` 会渲染为分割线

**第五项——退出登录**：
```html
<a @click="closeMenu" class="text-sm font-bold py-3">
  <UserLogoutIcon />
  退出登录
</a>
```
用的是 `<a>` 而不是 `<RouterLink>`，因为退出不需要跳转页面。`@click` 是 Vue 的事件监听语法，`@click="closeMenu"` 等价于 `v-on:click="closeMenu"`。注意这里还没绑定退出的业务逻辑（后面提交会补）

## 四、导航栏的登录状态响应

**文件**：`NavBar.vue`

```html
<!-- 已登录 → 显示"创作"按钮 -->
<RouterLink v-if="user.isLogin()" :to="{name: 'create-index'}" class="btn btn-ghost text-base mr-6">
  <CreateIcon />
  创作
</RouterLink>

<!-- 未登录 → 显示"登录"按钮 -->
<RouterLink v-if="!user.isLogin()" :to="{name: 'user-account-login-index'}" class="btn btn-ghost text-lg">
  登录
</RouterLink>

<!-- 已登录 → 显示用户下拉菜单 -->
<UserMenu v-else />
```

**三个关键 Vue 指令**：

- `v-if="user.isLogin()"` —— 条件渲染。值为真时渲染元素，为假时**完全移除 DOM 元素**（不是 `display:none`）

- `v-else` —— 必须紧跟在 `v-if` 或 `v-else-if` 的元素后面。当 `v-if` 的条件为 false 时渲染。这里的 `v-else` 匹配的是 `v-if="!user.isLogin()"`——未登录显示登录按钮，>否则<已登录显示用户菜单

**`v-if` vs `v-show` 的区别**：
- `v-if` —— 为假时元素**不存在于 DOM 树**中，切换开销大（要创建/销毁组件），但初始为假时完全不渲染，初始开销小
- `v-show` —— 为假时元素在 DOM 中但 `display:none`，始终渲染，只切换 CSS。适合频繁切换的场景
- 这里用 `v-if` 是因为登录状态通常只切换一次，不需要频繁切换

注意：侧边栏的"创作"按钮仍然存在。顶栏和侧边栏的"创作"都指向同一个路由，给用户多一个入口。
