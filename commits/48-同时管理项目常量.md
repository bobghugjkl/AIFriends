## 二、源码

### 2.1 `config.js`——前端配置集中管理（新文件，19行）

```javascript
const platform = 'django'   // vue、django、cloud

const CONFIG_API = {
    HTTP_URL: '',
    VAD_URL: '',
}

if (platform === 'vue') {
    CONFIG_API.HTTP_URL = 'http://127.0.0.1:8000'
    CONFIG_API.VAD_URL = 'http://localhost:5173/vad/'
} else if (platform === 'django') {
    CONFIG_API.HTTP_URL = 'http://127.0.0.1:8000'
    CONFIG_API.VAD_URL = 'http://127.0.0.1:8000/static/frontend/vad/'
} else if (platform === 'cloud') {
    CONFIG_API.HTTP_URL = 'https://app7492.acapp.acwing.com.cn'
    CONFIG_API.VAD_URL = 'https://app7492.acapp.acwing.com.cn/static/frontend/vad/'
}

export default CONFIG_API
```

**逐行讲解**：

- `const platform = 'django'` —— 当前环境标识。手动切换：`'vue'`（Vite 开发服务器）、`'django'`（本地 Django 生产部署）、`'cloud'`（云端服务器）
- `CONFIG_API` —— 配置对象，包含所有环境相关的 URL
- `HTTP_URL` —— 后端 API 地址。开发 (`vue`) 和本地部署 (`django`) 都用 `127.0.0.1:8000`；云端用 `https://app7492.acapp.acwing.com.cn`
- `VAD_URL` —— VAD ONNX 模型文件路径。开发阶段从 Vite dev server 加载 (`localhost:5173/vad/`)；django 模式从 Django static 目录加载；云端从 HTTPS 加载
- `export default CONFIG_API` —— ES Module 默认导出

**三个文件如何引用**：

```javascript
// api.js (改前: const BASE_URL = 'http://127.0.0.1:8000')
import CONFIG_API from "@/js/config/config.js";
const BASE_URL = CONFIG_API.HTTP_URL

// streamApi.js (改前: const BASE_URL = 'http://127.0.0.1:8000')
import CONFIG_API from "@/js/config/config.js";
const BASE_URL = CONFIG_API.HTTP_URL

// Microphone.vue (改前: const baseUrl = "http://localhost:5173/vad/")
import CONFIG_API from "@/js/config/config.js";
const baseUrl = CONFIG_API.VAD_URL
```

切换部署环境只需改 `config.js` 第一行的 `platform` 值，三处引用自动生效。

### 2.2 `settings.py`——开发/生产双模式

```python
ALLOWED_HOSTS = ['127.0.0.1', 'app7492.acapp.acwing.com.cn']
# ↑ 允许本地和云端域名访问
```

```python
if not DEBUG:
    STATIC_ROOT = BASE_DIR / 'static'  # 生产：python manage.py collectstatic 收集到此处
else:
    STATICFILES_DIRS = [               # 开发：Django 直接从这个目录查找静态文件
        BASE_DIR / 'static',
    ]
```

- `DEBUG = True`（开发）→ 使用 `STATICFILES_DIRS`，Django 直接从 `backend/static/` 读取静态文件。适合本地调试
- `DEBUG = False`（生产）→ 使用 `STATIC_ROOT`，需先运行 `collectstatic` 命令把所有静态文件复制到该目录。Nginx 直接从此目录提供文件，不经过 Django

```python
if DEBUG:
    MEDIA_URL = 'http://127.0.0.1:8000/media/'
else:
    MEDIA_URL = 'https://app7492.acapp.acwing.com.cn/media/'

MEDIA_ROOT = BASE_DIR / 'media'  # 两种模式共用同一个物理路径
```

- `MEDIA_ROOT` —— 用户上传文件的物理存储路径（两种模式一样）
- `MEDIA_URL` —— 前端访问媒体文件的 URL 前缀。开发时用本地地址，生产时用云端域名。Django 不直接 serve 媒体文件（由 Nginx 处理），但 `MEDIA_URL` 用于 `ImageField.url` 属性生成可访问的 URL
