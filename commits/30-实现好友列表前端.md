## 一、这次提交做了什么

## 二、`FriendIndex.vue`——好友列表页

和 `HomepageIndex.vue` 几乎一样的无限滚动逻辑，区别：
- API 调用 `/api/friend/get_list/`
- 卡片传 `canRemoveFriend="true"` + `friendId="..."` 让用户能删除好友
- 数据取 `data.friends`（好友列表），每条是 `friend.character`（嵌套的角色数据）
- 删除逻辑：`removeFriend(friendId)` 从本地列表中过滤掉

## 三、Character 卡片新增功能

### 3.1 删除好友按钮

```html
<div v-if="canRemoveFriend" class="absolute right-0 top-50">
  <button @click.stop="handleRemoveFriend" class="btn btn-circle btn-ghost">
    <RemoveIcon />
  </button>
</div>
```

**新增 Props**：
- `canRemoveFriend` —— 是否显示删除好友按钮
- `friendId` —— 好友关系 ID，用于删除 API

### 3.2 事件冒泡修复

```html
<button @click.stop="handleRemoveCharacter">
```

加 `.stop` 修饰符——`event.stopPropagation()`，阻止事件冒泡到外层 div。外层 div 的 `@click="openChatField"` 负责打开聊天框。如果点删除按钮时事件冒泡到外层，会变成**先删角色再弹出聊天框**的 bug。`.stop` 阻止冒泡，点击删除只触发删除逻辑。

同样 `@click.stop` 也加到了编辑链接（`RouterLink`）上。`RouterLink` 本身不会冒泡但点击按钮区域可能触发，加 `.stop` 保证点击编辑按钮时不会同时打开聊天框。

## 四、总结

| 页面 | API | canEdit | canRemoveFriend |
|------|-----|---------|-----------------|
| 首页 | `homepage/index` | false | false |
| 个人空间 | `character/get_list` | true | false |
| 好友列表 | `friend/get_list` | false | true |

Character 卡片通过 3 种 props 控制 3 种场景下的按钮显示。
