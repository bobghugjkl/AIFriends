## 二、使用了什么技术

| 技术 | 用途 |
|------|------|
| Tailwind CSS v4 | 原子化 CSS 框架，通过预定义 class（如 `flex`、`w-full`）直接在 HTML 中组合样式，无需手写 CSS（什么是"原子化CSS"？传统写CSS是给每个元素起名字再写样式规则：`.my-button { color: red; font-size: 16px; }`。原子化CSS的思路反过来——每个class只做一件事（一个"原子"），比如`text-red-500`只管颜色、`text-lg`只管字号。你直接在HTML标签上像搭积木一样组合这些class就能出样式，不用来回切换HTML和CSS文件，也不用纠结"这个div该起什么名字"。Tailwind提供了成千上万个这样的原子class） |
| DaisyUI v5 | 基于 Tailwind 的组件库，提供 `drawer`、`navbar`、`btn`、`menu` 等现成 UI 组件样式，仅通过 class 名使用，无需 JS |
| @tailwindcss/vite | Tailwind CSS 的 Vite 插件，在构建时扫描代码中的 class，按需生成 CSS |
| SVG 内联图标 | SVG 代码直接封装为 Vue 组件，通过 `stroke="currentColor"` 继承父元素文字颜色，自动适配主题 |
| Vue Slot 机制 | 通过 `<slot></slot>` 让父组件向子组件传递模板内容，实现布局与内容的解耦 |

## 三、整体架构 / 数据流

### 组件树

```
App.vue
 └── NavBar.vue  (DaisyUI Drawer 布局)
      ├── drawer-toggle  ← 隐藏 checkbox（控制侧边栏开关）
      ├── drawer-content
      │    ├── navbar (DaisyUI 顶部导航栏)
      │    │    ├── navbar-start → MenuIcon + "AIFriends" Logo
      │    │    ├── navbar-center → 搜索框 (join: input + SearchIcon 按钮)
      │    │    └── navbar-end → 登录按钮
      │    └── <slot></slot>  ← 页面内容由父组件注入
      └── drawer-side
           ├── drawer-overlay (点击遮罩关闭侧边栏)
           └── menu (DaisyUI 菜单列表)
                ├── HomepageIcon + "首页"
                ├── FriendIcon + "好友"
                └── CreateIcon + "创作"
```

### 交互流程

```
用户点击汉堡菜单按钮
       │
       ▼
label[for="my-drawer-4"] 被点击
       │
       ▼
input#my-drawer-4[type=checkbox] 切换 checked 状态
       │
       ▼
DaisyUI CSS :checked 伪类检测状态变化
       │
       ├── checked=true  → drawer-side 展开（显示图标+文字）
       └── checked=false → drawer-side 收起（只显示图标，悬停 tooltip）
```

整个交互**不依赖任何 JavaScript**，完全通过 CSS 机制实现。（什么是CSS的`:checked`机制？CSS里有一种叫"伪类"的选择器——`:checked`表示"被勾选的复选框"。当你点击`<label for="my-drawer-4">`时，浏览器自动把`id="my-drawer-4"`的checkbox勾上或取消，CSS立刻检测到状态变化，应用对应的样式。所以侧边栏的展开/收起不需要写一行JS逻辑——checkbox是状态存储，label是触发器，CSS :checked是状态检测器。这叫做"CSS-only交互"，是很巧妙的技巧）

#### 整体布局结构：DaisyUI 的 Drawer（抽屉）

```html
<div class="drawer lg:drawer-open">
```

**DaisyUI 的 Drawer 组件**是一个"侧边栏+主内容区"的布局。它通过一个隐藏的 `<input type="checkbox">` 控制侧边栏打开/关闭。

- `drawer` —— DaisyUI 的抽屉容器，包裹整个布局
- `lg:drawer-open` —— Tailwind 的响应式前缀。`lg:` 表示"在大屏幕（≥1024px）时"。`lg:drawer-open` 意思是**大屏幕上侧边栏始终展开**，小屏幕上侧边栏默认收起（点击汉堡按钮才打开）

整个 Drawer 的 HTML 结构有三部分：

```
drawer（容器）
├── <input class="drawer-toggle">   ← 控制开关的隐藏 checkbox
├── <div class="drawer-content">    ← 主内容区域
│     ├── <nav> 顶部导航栏
│     └── <slot> 页面内容
└── <div class="drawer-side">       ← 侧边栏
      ├── <label class="drawer-overlay">  点击遮罩关闭
      └── <ul class="menu">         ← 菜单列表
```

#### 隐藏的开关 checkbox

```html
<input id="my-drawer-4" type="checkbox" class="drawer-toggle" />
```

这是一个隐藏的复选框，DaisyUI 用 CSS `:checked` 伪类检测它有没有被勾选。当 `<label for="my-drawer-4">` 被点击时，这个 checkbox 的状态切换，侧边栏就打开/关闭。**不需要一行 JavaScript**，纯靠 CSS 机制实现交互。

#### 顶部导航栏

```html
<nav class="navbar w-full bg-base-100 shadow-sm">
```

- `navbar` —— DaisyUI 的导航栏组件，内部用 `navbar-start` / `navbar-center` / `navbar-end` 做左中右三栏布局
- `w-full` —— Tailwind class，`width: 100%`，占满宽度
- `bg-base-100` —— DaisyUI 的底色变量，白色/浅灰底色（取决于当前主题）
- `shadow-sm` —— Tailwind 小阴影，让导航栏和下方内容有层次感

**左栏**：
```html
<div class="navbar-start">
  <label for="my-drawer-4" aria-label="open sidebar" class="btn btn-square btn-ghost">
    <MenuIcon />
  </label>
  <div class="px-2 font-bold text-xl">AIFriends</div>
</div>
```
- `<label for="my-drawer-4">` —— 点击这个 label 时，浏览器会切换 `id="my-drawer-4"` 的 checkbox。这就是侧边栏的开关机制——点汉堡菜单按钮 → checkbox 勾选 → 侧边栏出现。
- `btn btn-square btn-ghost` —— DaisyUI 按钮样式：`btn` = 基础按钮，`btn-square` = 正方形边框，`btn-ghost` = 无背景色只有悬停效果
- `<MenuIcon />` —— 汉堡菜单图标（三条横线）
- `font-bold text-xl` —— Tailwind 工具类：加粗 + 1.25rem 字号

**中栏**（搜索框）：
```html
<div class="navbar-center w-4/5 max-w-180">
  <div class="join w-4/5">
    <input class="input join-item rounded-l-full w-4/5" placeholder="搜索你感兴趣的内容" />
```

- `rounded-l-full` / `rounded-r-full` —— 左圆角 / 右圆角。输入框左边圆、按钮右边圆，合在一起像一个胶囊形搜索框

#### `<slot></slot>` —— 页面内容占位

```html
<slot></slot>
```

`<slot>` 是 Vue 的**插槽**。当父组件这样写：
```html
<NavBar>
  这是页面内容
</NavBar>
```
`"这是页面内容"` 就会渲染在 `<slot></slot>` 的位置。这样 NavBar 只管布局，页面内容由使用者决定。

#### 侧边栏

```html
<div class="drawer-side is-drawer-close:overflow-visible">
  <label for="my-drawer-4" aria-label="close sidebar" class="drawer-overlay"></label>
  <div class="flex min-h-full flex-col items-start bg-base-200 is-drawer-close:w-16 is-drawer-open:w-54">
    <ul class="menu w-full grow">
      <!-- 菜单项 -->
    </ul>
  </div>
</div>
```

- `drawer-side` —— DaisyUI 的侧边栏容器，会自动定位在左侧，宽度可收缩
- `drawer-overlay` —— 半透明遮罩层（小屏幕时点侧边栏外面就能关闭）
- `is-drawer-close:w-16` / `is-drawer-open:w-54` —— DaisyUI 的状态感知 class。侧边栏关闭时宽 `w-16`（64px，只够放图标），打开时宽 `w-54`（216px，够放图标+文字）。DaisyUI 根据 checkbox 状态自动切换这些 class
- `bg-base-200` —— 浅灰背景，和主内容区区分

#### 菜单项（以首页为例）

```html
<li>
  <button class="is-drawer-close:tooltip is-drawer-close:tooltip-right py-3" data-tip="首页">
    <HomepageIcon />
    <span class="is-drawer-close:hidden text-base ml-2 whitespace-nowrap">首页</span>
  </button>
</li>
```

- `is-drawer-close:tooltip is-drawer-close:tooltip-right` —— 侧边栏关闭时（只显示图标），鼠标悬停出现的提示文字。DaisyUI 的 tooltip 组件
- `data-tip="首页"` —— DaisyUI tooltip 的提示内容通过 `data-tip` 属性设置（tooltip就是"鼠标悬停时弹出的小气泡提示"——侧边栏关闭时只显示图标，用户不知道每个图标代表什么，鼠标放上去弹出"首页""好友""创作"这些文字提示，移开就消失）
- `is-drawer-close:hidden` —— 侧边栏关闭时隐藏文字（只显示图标），展开时显示文字
- `whitespace-nowrap` —— 文字不换行，保持一行

### 3.4 五个图标组件

以 `HomepageIcon.vue` 为例：

```vue
<template>
  <svg xmlns="http://www.w3.org/2000/svg"
    viewBox="0 0 24 24"
    stroke-linejoin="round"
    stroke-linecap="round"
    stroke-width="2"
    fill="none"
    stroke="currentColor"

```

**SVG 属性解释**：
- `viewBox="0 0 24 24"` —— 画布坐标系为 24×24 的小方格。所有 path 的坐标都在这个范围内
- `stroke="currentColor"` —— 线条颜色继承父元素的文字颜色（`color` 属性），这样图标颜色自动跟随主题
- `stroke-width="2"` —— 线条粗细为 2px
- `stroke-linecap="round"` —— 线条端点圆头
- `stroke-linejoin="round"` —— 线条拐角圆角
- `fill="none"` —— 不填充内部区域（只画线条轮廓）
- `class="inline-block size-6"` —— Tailwind class，让 SVG 成为行内块元素，尺寸 24px×24px

## 六、Django 模板小调整

`backend/web/templates/index.html`：
```diff
-    <script type="module" crossorigin src="{% static 'frontend/assets/index-DM0D-WOo.js' %}"></script>
-    <link rel="stylesheet" crossorigin href="{% static 'frontend/assets/index-X3LBb3Aa.css' %}">
+    <script type="module" crossorigin src="{% static 'frontend/assets/index-FirstBlood.js' %}"></script>
+    <link rel="stylesheet" crossorigin href="{% static 'frontend/assets/index-FirstBlood.css' %}">
```

**讲解**：Vite 打包时会给文件名加内容哈希（content hash）来缓存管理——文件内容变了，哈希就变，浏览器就会下载新版本。这里的 `FirstBlood` 就是哈希值。作者重新 build 了前端，Django 模板里引用的文件名也要同步更新。（什么是"内容哈希"？就是对文件内容做一个"指纹运算"——比如文件内容是"hello"，经过MD5算法得到`5d41402abc4b2a76b9719d911017c592`，取前几位拼到文件名里。如果文件内容改了一个字，指纹就完全不一样了。为什么要这么做？浏览器默认会缓存JS/CSS文件——第一次下载后下次直接用缓存，加速加载。但如果你更新了代码，文件名不变，浏览器不知道文件已经改了，用户看到的还是旧版。加了内容哈希后：旧代码→旧文件名（缓存着）→新代码→新文件名（浏览器不认识，重新下载）。两全其美：没改动的文件继续用缓存，改动的文件自动刷新）
