## 一、这次提交做了什么

解决了 SPApp 的一个核心问题：**用户登录后刷新页面，怎么保持登录状态？**

具体实现了：
1. 后端新增 `get_user_info` API——用 Cookie 中的 Refresh Token 验证身份并返回用户信息
2. 前端 `App.vue` 在页面首次加载时调用该 API，恢复用户登录状态
3. 路由添加 `meta.needLogin` 标记——需要登录才能访问的页面，未登录自动跳转到登录页
4. 解决"闪烁"问题——在确认用户登录状态之前，导航栏不显示"登录"按钮

---

## 二、为什么需要这个功能

SPA 中 JS 变量存在内存里，刷新页面后变量全部销毁。不处理的话，用户登录后刷新页面 → Store 里的 `accessToken` 丢失 → `isLogin()` 返回 false → 页面显示"未登录"。但服务端 Cookie 里还有 Refresh Token——可以用它来恢复登录状态。

## 三、后端：`GetUserInfoView`

**文件**：`backend/web/views/user/account/get_user_info.py`（新文件）

```python
from rest_framework.response import Response
from rest_framework.views import APIView
from rest_framework.permissions import IsAuthenticated

from web.models.user import UserProfile


class GetUserInfoView(APIView):
    permission_classes = [IsAuthenticated]
    def get(self, request):
        try:
            user = request.user
            user_profile = UserProfile.objects.get(user=user)
            return Response({
                'result': 'success',
                'user_id': user.id,
                'username': user.username,
                'photo': user_profile.photo.url,
                'profile': user_profile.profile,
            })
        except:
            return Response({
                'result': '系统异常，请稍后重试'
            })
```

**讲解**：

- `permission_classes = [IsAuthenticated]` —— 必须携带有效的 Access Token 才能访问。如果没有 Token 或 Token 过期，DRF 自动返回 401
- `def get(self, request):` —— 使用 GET 方法（获取用户信息是读操作，RESTful 规范用 GET）
- `request.user` —— DRF 的 JWT 认证中间件验证 Token 后，自动把对应的 `User` 对象附加到 `request.user` 上。开发者不需要手动解析 Token、查数据库
- `user_profile = UserProfile.objects.get(user=user)` —— 这次用的是正确的查询方式（`user=user`）
- 返回的数据结构和登录/注册接口一致——前端用同一个 `setUserInfo()` 处理

**路由注册**：`/api/user/account/get_user_info/`

## 四、前端：`App.vue`——页面加载时拉取用户信息

```javascript
onMounted(async () => {
  try {
    const res = await api.get('/api/user/account/get_user_info/')
    const data = res.data
    if (data.result === 'success') {
      user.setUserInfo(data)
    }
  } catch (err) {
  } finally {
    user.setHasPulledUserInfo(true)

    if (route.meta.needLogin && !user.isLogin()) {
      await router.replace({
        name: 'user-account-login-index',
      })
    }
  }
})
```

**逐行讲解**：

- `onMounted(async () => {...})` —— Vue 3 的**生命周期钩子**。`onMounted` 中的回调在组件被挂载到 DOM 后执行（只执行一次）。`async` 让它支持 `await`

- `api.get('/api/user/account/get_user_info/')` —— 发 GET 请求。请求拦截器会自动带上 Access Token（如果 Cookie 里有有效的 Refresh Token，响应拦截器会自动刷新 Access Token）

- `catch (err) {}` —— 故意空了 catch。用户的 Refresh Token 过期是正常情况（7 天没访问），不应该报错，静默处理即可

- `finally { user.setHasPulledUserInfo(true) }` —— **关键变量**。不管拉取成功还是失败，都标记"已经尝试过拉取"。这个标志用于解决导航栏的"闪烁"问题

- `if (route.meta.needLogin && !user.isLogin())` —— 当前页面需要登录且用户未登录，自动跳转到登录页

- `router.replace()` vs `router.push()` —— `replace` 替换当前历史记录，用户点"返回"不会回到需要登录的页面；`push` 添加新记录会让用户返回后再次被重定向

**刷新页面后恢复登录的完整流程**：

1. 页面加载 → Vue 创建 → `App.vue` 挂载 → `onMounted` 执行
2. 发 `GET /get_user_info/` → 拦截器检查无 Access Token → 不发这个请求（跳转到步骤3）
3. 请求到后端 → 返回 401 → 响应拦截器检测到 401
4. 响应拦截器用 Cookie 中的 Refresh Token 刷新 Access Token → 成功 → 重试原请求
5. 这次带上新的 Access Token → 后端返回用户信息 → `setUserInfo(data)` 恢复登录状态
6. 最终 `setHasPulledUserInfo(true)` → 导航栏重新渲染，显示用户头像

## 五、`hasPulledUserInfo` 解决闪烁问题

**Store 新增**：

```javascript
const hasPulledUserInfo = ref(false)

function setHasPulledUserInfo(newStatus) {
    hasPulledUserInfo.value = newStatus
}
```

**NavBar 使用**：

```html
<RouterLink v-if="user.hasPulledUserInfo && !user.isLogin()" :to="...">
  登录
</RouterLink>
<UserMenu v-else-if="user.isLogin()" />
```

**问题**：页面加载时 Store 初始值是空（`accessToken = ''`，`isLogin() = false`）。如果只有一个 `v-if="!user.isLogin()"` 就显示登录按钮，用户刷新后会看到：
1. 先闪现"登录"按钮（因为初始值空）
2. `get_user_info` 返回，恢复登录状态
3. "登录"按钮消失，变成用户头像

这叫"闪烁"（Flash of Incorrect State）。

**解决**：加了 `hasPulledUserInfo` 作为第三态。在 API 返回之前，`hasPulledUserInfo` 是 `false`，此时**既不显示登录按钮也不显示头像**（两个条件都不满足），导航栏右侧为空。API 返回后，`hasPulledUserInfo` 变成 `true`，根据实际情况渲染正确的 UI。

## 六、路由守卫：`beforeEach`

**文件**：`router/index.js`

每个路由加了 `meta: { needLogin: true/false }`：

| 页面 | needLogin | 原因 |
|------|-----------|------|
| 首页 | false | 谁都能看 |
| 好友 | true | 需要登录看自己的好友 |
| 创作 | true | 需要登录才能创建角色 |
| 登录/注册 | false | 登录前就要访问 |
| 个人空间 | false | 游客也能看别人的空间 |
| 编辑资料 | true | 只能编辑自己的资料 |
| 404 | false | 谁都有可能碰到 |

```javascript
router.beforeEach((to, from) => {
  const user = useUserStore()
  if (to.meta.needLogin && user.hasPulledUserInfo && !user.isLogin()) {
    return {
      name: 'user-account-login-index'
    }
  }
  return true
})
```

**逐行讲解**：

- `router.beforeEach((to, from) => {...})` —— **全局前置路由守卫**。每次导航发生前都会执行这个回调
- `to` —— 目标路由对象；`from` —— 来源路由对象
- `to.meta.needLogin` —— 读取路由配置中的 `meta` 元数据
- `user.hasPulledUserInfo && !user.isLogin()` —— 只有在"确认了用户状态"且"确实未登录"时才拦截。如果 `hasPulledUserInfo` 为 false（还在拉取中），守卫不拦截——等 `get_user_info` 完成后会根据最终状态重定向
- `return {name: 'user-account-login-index'}` —— 返回一个路由对象 = 重定向到登录页
- `return true` —— 返回 true = 允许导航

**`beforeEach` 和 `onMounted` 的分工**：
- `beforeEach` 处理**页面间跳转**的场景（用户在已登录状态下手动输地址）
- `onMounted` 处理**首次加载/刷新**的场景（服务端拉取用户信息后判断）

两者配合覆盖所有场景。

## 七、总结

| 新增/修改 | 作用 |
|-----------|------|
| `GetUserInfoView` | 根据 JWT 返回当前用户信息 |
| `App.vue` `onMounted` | 首次加载时拉取用户信息，恢复登录状态 |
| `hasPulledUserInfo` | 解决"拉取完成前"的 UI 闪烁问题 |
| `router.beforeEach` | 路由守卫，未登录跳转到登录页 |
| `meta.needLogin` | 标记每个路由是否需要登录 |

**从用户体验角度看**：登录后关闭浏览器，再次打开 → 只要 Refresh Token 还没过期（7天），页面自动识别身份，无缝恢复登录状态，不需要重新输入用户名密码。
