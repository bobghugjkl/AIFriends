## 二、使用了什么技术

| 技术/工具/库 | 用途 |
|-------------|------|
| Django re_path / 正则路由 | 添加通配 URL 匹配规则，将所有非 media/static/assets 的请求返回 index.html，解决 SPA 刷新 404 问题 |
| 正则表达式负向前瞻 (?!...) | 排除 media/、static/、assets/ 前缀的 URL，确保文件访问不受影响 |
| Tailwind CSS (w-52/w-48, break-all) | 下拉菜单宽度微调（208px→192px）和长用户名强制换行，防止 UI 溢出 |
| Vue Router History 模式 | 使用 HTML5 History API 管理前端路由，URL 不带 # 号，但需服务端配合将所有非文件路径指向 index.html |
| Django URL 调度器 (urlpatterns) | Django 按 urlpatterns 列表顺序逐一匹配请求 URL，匹配成功则执行对应视图函数，未匹配返回 404 |
| SPA (Single Page Application) 架构 | 单页应用模式，页面切换由 Vue Router 在前端完成，服务端仅需提供一份入口 index.html |

## 四、修复1：Django 通配 URL 匹配

**文件**：`backend/web/urls.py`

```diff
-from django.urls import path
+from django.urls import path, re_path
+    re_path(r'^(?!media/|static/|assets/).*$', index)
```

**这个问题是什么**：前端是一个 SPA，所有页面都由前端路由处理（通过 Vue Router 的 History 模式）。但用户刷新浏览器时，浏览器会向服务器请求当前 URL。

例如用户在 `/user/space/1/` 刷新页面 → 浏览器向 Django 发送 `GET /user/space/1/` → Django 的路由表里没有这条 → 返回 404 → 用户看到白屏或错误页面。

**解决方案**：添加一条通配正则路由 `re_path(r'^(?!media/|static/|assets/).*$', index)`，表示"所有不以 `media/`、`static/`、`assets/` 开头的 URL，全部返回 `index.html`"。浏览器加载 `index.html` → Vue 应用启动 → Vue Router 解析当前 URL → 渲染正确的页面。

**`re_path` vs `path` 的区别**：
- `path()` —— Django 的简洁路由函数，用 `<参数>` 做匹配
- `re_path()` —— Django 的正则路由函数，用 Python 正则表达式做匹配，更灵活

**正则表达式 `^(?!media/|static/|assets/).*$` 逐段讲解**：
- `^` —— 匹配字符串开头
- `(?!media/|static/|assets/)` —— **负向前瞻**（negative lookahead）。"当前位置后面不能是 media/、static/ 或 assets/"
- `.*` —— 匹配任意字符（除换行）零次或多次
- `$` —— 匹配字符串结尾

整体含义：匹配所有 URL，但排除以 `media/`、`static/`、`assets/` 开头的。这些被排除的 URL 由 Django 自己的 static/media 处理器处理（文件访问）。（"负向前瞻"就像机场安检的"免检名单"——所有人（所有URL）都要排队过安检，但穿"media/""static/""assets/"制服的（以这些前缀开头的URL）不用查，直接放行。为什么要排除它们？因为这些路径指向真实的静态文件（图片、CSS、JS），Django需要直接返回文件内容而不是index.html——如果连图片请求都返回HTML页面，整个网站的图片就全坏了）

## 五、修复2：下拉菜单宽度微调

**文件**：`UserMenu.vue`

```diff
-    <ul tabindex="-1" class="dropdown-content menu bg-base-100 rounded-box z-1 w-52 p-2 shadow-lg">
+    <ul tabindex="-1" class="dropdown-content menu bg-base-100 rounded-box z-1 w-48 p-2 shadow-lg">
```

- `w-52` → `w-48`：Tailwind 中 `w-52`=208px，`w-48`=192px。菜单稍微窄了 16px，视觉上更紧凑

```diff
-          <span class="text-base font-bold line-clamp-1">{{ user.username }}</span>
+          <span class="text-base font-bold line-clamp-1 break-all">{{ user.username }}</span>
```

- 加了 `break-all`：对于非常长的用户名（如一个超长邮箱），在菜单项容器内强制换行，不会撑破菜单宽度
