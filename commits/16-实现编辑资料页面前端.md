## 二、使用了什么技术

| 技术/工具/库 | 用途 |
|-------------|------|
| Croppie（图片裁剪库） | 实现头像图片的裁剪、拖动、缩放、旋转功能，输出裁剪后的 Base64 图片数据（Base64是什么？一种把二进制数据（如图片）转成纯文本的编码方式。图片文件本质上是0101的二进制数据，无法直接放在JSON或HTML里。Base64把这些二进制数据翻译成64个可打印字符（A-Z, a-z, 0-9, +, /），变成一长串文本。比如一张小图片可以变成`data:image/png;base64,iVBORw0KGgo...`这样的字符串——这个字符串可以直接贴在HTML的`<img src="...">`里，也可以放在JSON里传给服务器。缺点是体积会膨胀约33%（3个字节变成4个字符），但换来了"到处可放"的便利性。在浏览器里，`FileReader.readAsDataURL()`自动帮你把图片文件转成Base64字符串，Croppie裁剪后的结果也是Base64字符串）
| useTemplateRef + defineExpose（Vue 3） | 父组件通过模板引用获取子组件实例，子组件通过 defineExpose 暴露内部数据，实现"父读取子"的数据收集模式 |
| FileReader.readAsDataURL | 浏览器原生 API，将用户选择的图片文件（File）读取为 Base64 data URL，供 Croppie 和预览使用 |
| FormData（multipart/form-data） | 构造包含文本字段和图片文件的请求体，通过 POST 发送到后端更新接口 |
| Base64 编解码 | Croppie 输出 Base64 格式的裁剪结果，通过 base64ToFile 工具函数转为 File 对象后放入 FormData |
| DaisyUI modal | 模态弹窗作为 Croppie 裁剪器的容器，点击头像时弹出裁剪界面 |
| Vue 3 Composition API (ref, watch, nextTick, onBeforeUnmount) | 响应式状态声明、props 变化监听、DOM 更新等待、组件销毁前清理 Croppie 实例 |
| Vue defineProps / 单向数据流 | 父组件通过 props 向子组件传递初始值，子组件不可直接修改 props，需创建本地 ref 副本进行编辑 |
| HTML `<input type="file">` 文件选择 | 浏览器原生文件选择控件，change 事件通过 e.target.files 获取用户选择的 File 对象，支持重置 value 重复选择 |
| Axios POST (FormData) | 发送 multipart/form-data 格式的 POST 请求，自动识别内容类型并设置正确的 Content-Type 头 |

### 4.1 `base64_to_file.js`——Base64 转文件工具

**文件**：`frontend/src/js/utils/base64_to_file.js`（新文件，完整内容）

```javascript
export function base64ToFile(base64, filename) {
  const arr = base64.split(',')
  const mime = arr[0].match(/:(.*?);/)[1]
  const bstr = atob(arr[1])
  let n = bstr.length
  const u8arr = new Uint8Array(n)
  while (n--) u8arr[n] = bstr.charCodeAt(n)
  return new File([u8arr], filename, { type: mime })
}
```

### 4.2 `ProfileIndex.vue`——编辑资料主页面

**文件**：`frontend/src/views/user/profile/ProfileIndex.vue`（完整内容）

```vue
<script setup>
import Photo from "@/views/user/profile/components/Photo.vue";
import Username from "@/views/user/profile/components/Username.vue";
import Profile from "@/views/user/profile/components/Profile.vue";
import {useUserStore} from "@/stores/user.js";
import {ref, useTemplateRef} from "vue";
import {base64ToFile} from "@/js/utils/base64_to_file.js";
import api from "@/js/http/api.js";

const user = useUserStore()

const photoRef = useTemplateRef('photo-ref')
const usernameRef = useTemplateRef('username-ref')
const profileRef = useTemplateRef('profile-ref')
const errorMessage = ref('')

async function handleUpdate() {
  const photo = photoRef.value.myPhoto
  const username = usernameRef.value.myUsername.trim()
  const profile = profileRef.value.myProfile.trim()

  errorMessage.value = ''
  if (!photo) {
    errorMessage.value = '头像不能为空'
  } else if (!username) {
    errorMessage.value = '用户名不能为空'
  } else if (!profile) {
    errorMessage.value = '简介不能为空'
  } else {
    const formData = new FormData()
    formData.append('username', username)
    formData.append('profile', profile)
    if (photo !== user.photo) {
      formData.append('photo', base64ToFile(photo, 'photo.png'))
    }
    try {
      const res = await api.post('/api/user/profile/update/', formData)
      const data = res.data
      if (data.result === 'success') {
        user.setUserInfo(data)
      } else {
        errorMessage.value = data.result
      }
    } catch (err) {
      console.log(err)
    }
  }
}
</script>

<template>
  <div class="flex justify-center">
    <div class="card w-120 bg-base-200 shadow-sm mt-16">
      <div class="card-body">
        <h3 class="text-lg font-bold my-4">编辑资料</h3>
        <Photo ref="photo-ref" :photo="user.photo" />
        <Username ref="username-ref" :username="user.username" />
        <Profile ref="profile-ref" :profile="user.profile" />

        <p v-if="errorMessage" class="text-sm text-red-500">{{ errorMessage }}</p>

        <div class="flex justify-center">
          <button @click="handleUpdate" class="btn btn-neutral w-60 mt-2">更新</button>
        </div>
      </div>
    </div>
  </div>
</template>

<style scoped>

</style>
```

**核心模式——`useTemplateRef` + `defineExpose`**：

1. 父组件用 `useTemplateRef('photo-ref')` 获取子组件实例
2. 子组件用 `defineExpose({myPhoto})` 暴露内部数据
3. 父组件用 `photoRef.value.myPhoto` 读取子组件的数据

**为什么不用 v-model**：v-model 适合简单值（如字符串）。这里有 3 个子组件，如果用 v-model，每个都需要 emit 事件，而用 ref + expose 一次就能拿到所有值。这是一种"命令式"的数据访问方式。

**提交逻辑**：

- `new FormData()` —— 浏览器原生 API，用于构造 `multipart/form-data` 格式的请求体。上传文件必须用这个，不能传 JSON
- `if (photo !== user.photo)` —— 用户没改头像就不上传，节省带宽和后端处理
- `base64ToFile(photo, 'photo.png')` —— Base64 → File 对象 → FormData → 发给后端

### 4.3 `Photo.vue`——头像裁剪组件

**文件**：`frontend/src/views/user/profile/components/Photo.vue`（完整内容）

```vue
<script setup>
import {nextTick, onBeforeUnmount, ref, useTemplateRef, watch} from "vue";
import CameraIcon from "@/views/user/profile/components/icon/CameraIcon.vue";
import Croppie from 'croppie'
import 'croppie/croppie.css'

const props = defineProps(['photo'])
const myPhoto = ref(props.photo)

watch(() => props.photo, newVal => {
  myPhoto.value = newVal
})

const fileInputRef = useTemplateRef('file-input-ref')
const modalRef = useTemplateRef('modal-ref')
const croppieRef = useTemplateRef('croppie-ref')
let croppie = null

async function openModal(photo) {
  modalRef.value.showModal()
  await nextTick()

  if (!croppie) {
    croppie = new Croppie(croppieRef.value, {
      viewport: {width: 200, height: 200, type: 'square'},
      boundary: {width: 300, height: 300},
      enableOrientation: true,
      enforceBoundary: true,
    })
  }

  croppie.bind({
    url: photo,
  })
}

async function crop() {
  if (!croppie) return

  myPhoto.value = await croppie.result({
    type: 'base64',
    size: 'viewport',
  })

  modalRef.value.close()
}

function onFileChange(e) {
  const file = e.target.files[0]
  e.target.value = ''
  if (!file) return

  const reader = new FileReader()
  reader.onload = () => {
    openModal(reader.result)
  }

  reader.readAsDataURL(file)
}

onBeforeUnmount(() => {
  croppie?.destroy()
})

defineExpose({
  myPhoto,
})
</script>

<template>
  <div class="flex justify-center">
    <div class="avatar relative">
      <div class="w-28 rounded-full">
        <img :src="myPhoto" alt="">
      </div>
      <div @click="fileInputRef.click()" class="absolute left-0 top-0 w-28 h-28 flex justify-center items-center bg-black/20 rounded-full cursor-pointer">
        <CameraIcon />
      </div>
    </div>
  </div>

  <input ref="file-input-ref" type="file" accept="image/*" class="hidden" @change="onFileChange">

  <dialog ref="modal-ref" class="modal">
    <div class="modal-box transition-none">
      <button @click="modalRef.close()" class="btn btn-circle btn-sm btn-ghost absolute right-2 top-2">✕</button>

      <div ref="croppie-ref" class="flex flex-col justify-center my-4"></div>

      <div class="modal-action">
        <button @click="modalRef.close()" class="btn">取消</button>
        <button @click="crop" class="btn btn-neutral">确定</button>
      </div>
    </div>
  </dialog>
</template>

<style scoped>

</style>
```

- `defineProps(['photo'])` —— 接收父组件传来的当前头像 URL（props）
- `watch(() => props.photo, newVal => { myPhoto.value = newVal })` —— 监听 props 变化。父组件的 `user.photo` 更新后，子组件自动同步。`watch` 的第一个参数是一个 getter 函数 `() => props.photo`，Vue 追踪这个函数的依赖。（什么是watch？就像你安排了一个"哨兵"盯梢某个变量——你告诉Vue"帮我盯着`props.photo`"，当它的值变了，Vue自动叫醒你并告诉你新值是多少。为什么需要watch？因为props是异步到达的——编辑页面打开时，`get_user_info` API可能还没返回，props.photo初始是空字符串，等API返回后变成真实URL。没有watch的话，输入框里就一直显示空白。watch让子组件在prop变化时自动同步到本地副本`myPhoto`，用户看到的输入框内容就会自动更新）
- `await nextTick()` —— Vue 异步更新 DOM，`showModal()` 后 DOM 还没完全渲染，`croppieRef.value` 可能是 `null`。`nextTick` 等 DOM 更新完成后才继续。（为什么需要nextTick？Vue为了提高性能，不会在你每次改数据后立刻更新页面——它会攒一批修改然后一次性更新DOM。就像餐厅服务员不会你点一个菜就跑一趟厨房，而是记下所有菜后一次性下单。但有时候你需要页面更新完之后才能做下一步操作（比如要在刚弹出来的模态框里初始化Croppie），这时候`await nextTick()`就是告诉Vue："我不催你，但你能不能在下一次更新完成后通知我一声？"——它就像一个"等页面渲染好"的信号）
- `new Croppie(element, options)` —— 在指定 DOM 元素上创建裁剪器
- `viewport: {width: 200, height: 200, type: 'square'}` —— 裁剪窗口是 200×200 的正方形
- `croppie.bind({url: photo})` —— 将图片加载到裁剪器。URL 可以是远程地址或 Base64
- `FileReader.readAsDataURL(file)` —— 浏览器原生 API，把用户选的图片文件转成 Base64 data URL
- `e.target.value = ''` —— 重置 `<input type="file">` 的值。如果不重置，用户再次选择同一张图时不会触发 `change` 事件（因为值没变）
- `onBeforeUnmount(() => { croppie?.destroy() })` —— 可选链调用，croppie 为 null 时不报错
