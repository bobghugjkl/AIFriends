## 一、这次提交做了什么

给 AI 增加**知识库搜索（RAG）**能力——新增 `search_knowledge_base` 工具函数，AI 可以从本地 LanceDB 向量数据库中检索相关文档片段，基于检索到的资料回答问题。（什么是RAG？Retrieval-Augmented Generation，检索增强生成。AI大模型虽然知识面广，但它的知识截止于训练日期，不知道训练之后发生的事情，也不知道你公司的内部文档。RAG的思路是：当用户问问题时，先去一个"资料库"里搜相关文档，把搜到的内容连同问题一起喂给AI，AI基于这些资料回答。就像考试时允许你翻书——AI的知识=它训练时学到的"底子"，RAG提供的搜索结果=你可以临时翻阅的"参考书"。所以即使AI不知道"阿里云百炼平台怎么开通"，只要你的资料库里有相关文档，它就能基于检索到的文档片段给出正确回答）

#### 新增 `search_knowledge_base` 工具

```python
        @tool
        def search_knowledge_base(query: str) -> str:
            """当用户查询阿里云百炼平台的相关信息时，调用此函数。输入为要查询的问题，输出为查询结果。"""
            db = lancedb.connect('./web/documents/lancedb_storage')
            embeddings = CustomEmbeddings()
            vector_db = LanceDB(
                connection=db,
                embedding=embeddings,
                table_name='my_knowledge_base',
            )
            docs = vector_db.similarity_search(query, k=3)
            context = '\n\n'.join([f'内容片段：{i + 1}\n{doc.page_content}' for i, doc in enumerate(docs)])
            return f'从知识库中找到以下相关信息：\n\n{context}\n'
```

**逐行讲解**：

- `@tool` —— LangChain 装饰器，把函数标记为 AI 可调用的工具。docstring `"""当用户查询阿里云百炼平台的相关信息时..."""` 会发送给 AI，告诉它什么情况下该用这个工具
- `lancedb.connect('./web/documents/lancedb_storage')` —— 打开 LanceDB 数据库。LanceDB 是文件型数据库，`connect` 只需传目录路径，不需要数据库连接字符串、用户名密码。数据存在 `lancedb_storage/` 目录下的 `.lance` 文件中
- `CustomEmbeddings()` —— 创建 embedding 实例。内部调用 DeepSeek `text-embedding-v4` API，把文本转成 1024 维数值向量。（什么是embedding/向量？embedding是把一段文字"翻译"成一串数字——比如"今天天气真好"变成`[0.23, -0.87, 0.45, ..., 0.12]`这样1024个小数组成的数组。这串数字不是随机的——语义相近的文字，它们的向量在数学上也更"近"。比如"今天天气真好"和"今天是个大晴天"的向量距离很近，而和"量子力学公式推导"的向量距离很远。这就像给每段文字标了一个GPS坐标——意思相近的文字坐标也近。向量数据库就是利用这个特性：你搜"阿里云百炼开通"，它把这句话也转成向量，然后在数据库中找向量最接近的文档。不需要关键词精确匹配，"百炼平台怎么申请"也能搜到"阿里云百炼开通流程"的文档。embedding模型（如DeepSeek text-embedding-v4）就是训练来专门干这个"文字→数字"翻译的神经网络）
- `LanceDB(connection=db, embedding=embeddings, table_name='my_knowledge_base')` —— LangChain 封装的 LanceDB 接口。`embedding=embeddings` 告诉它"用这个 embedding 类把查询文字转成向量"
- `vector_db.similarity_search(query, k=3)` —— **核心操作**。把 `query` 转成向量 → 在数据库所有文档向量中找最相似的 3 个（余弦相似度） → 返回 3 个 `Document` 对象（包含文本内容和元数据）。（什么是"余弦相似度"？一种计算两个向量"方向有多接近"的数学方法。值在-1到1之间——1表示方向完全一致（意思最接近），0表示毫无关系，-1表示方向完全相反。在二维平面上想象：如果你的问题向量指向"东北"，知识库里有三个文档的向量分别指向"东北偏北""正东""西南"，那么"东北偏北"的余弦相似度最高、最相关。`k=3`表示只取最相似的前3个——你不希望给AI塞太多无关文档，3个左右的精华片段刚好）
- `context = '\n\n'.join([f'内容片段：{i + 1}\n{doc.page_content}' for i, doc in enumerate(docs)])` —— 列表推导式拼接 3 个文档片段。`doc.page_content` 是片段文本。结果形如："内容片段：1\n...\n\n内容片段：2\n..."
- `return f'从知识库中找到以下相关信息：\n\n{context}\n'` —— 加上引导语返回。AI 看到这段文字后就知道"这是从知识库查到的资料，我要基于这些回答"

## 三、RAG 数据流

```
用户问："阿里云百炼怎么开通？"
    │
    ▼
agent (LLM with bound tools)
    │
    ├── LLM 判断：这个问题需要查知识库
    │   输出 tool_calls=[{name:'search_knowledge_base', args:{query:'阿里云百炼怎么开通'}}]
    │
    ▼
search_knowledge_base(query)
    │
    ├── lancedb.connect() 打开数据库
    ├── CustomEmbeddings.embed_query(query) 把问题转成 1024 维向量
    ├── LanceDB.similarity_search(k=3) 余弦相似度找 top-3
    │    结果：[片段1, 片段2, 片段3]（每个 ~500 字的文档块）
    ├── 拼接为上下文字符串
    └── return "从知识库中找到以下相关信息：..."
    │
    ▼
agent (LLM 收到上下文)
    │
    ├── LLM 基于【系统提示词 + 知识库上下文 + 用户问题】生成回复
    └── "阿里云百炼的开通流程是：1. 登录阿里云官网 2. ..."
```
