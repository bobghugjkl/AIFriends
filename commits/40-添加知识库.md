## 二、什么是向量数据库和 RAG

AI 大模型的知识截止于训练日期，不知道"你的产品怎么用"这种内部信息。RAG 的思路是：

1. 把文档切成片段 → 用 embedding 模型把每个片段转成向量（一组数字表示语义）
2. 存到向量数据库
3. 用户问问题时，把问题也转成向量 → 在数据库中找最相似的片段
4. 把找到的文档片段拼到 AI 的上下文中 → AI 基于这些"参考资料"回答问题

**为什么叫向量数据库**：它存的是"向量"（数字数组），不是传统的行列数据。查询用的是"相似度计算"而不是精确匹配。

## 三、新增工具：`search_knowledge_base`

```python
@tool
def search_knowledge_base(query: str) -> str:
    """当用户查询阿里云百炼平台的相关信息时，调用此函数。"""
    db = lancedb.connect('./web/documents/lancedb_storage')
    embeddings = CustomEmbeddings()
    vector_db = LanceDB(
        connection=db,
        embedding=embeddings,
        table_name='my_knowledge_base',
    )
    docs = vector_db.similarity_search(query, k=3)   # 找最相似的3个片段
    context = '\n\n'.join(...)
    return f'从知识库中找到以下相关信息：\n\n{context}\n'

tools = [get_time, search_knowledge_base]
```

**逐行讲解**：

- `lancedb.connect(...)` —— LanceDB 是一个开源的**本地**向量数据库，数据存在磁盘文件里，不需要另外安装服务
- `CustomEmbeddings()` —— 自定义的 embedding 类（调用 DeepSeek 的 embedding API 把文字转成向量）
- `LanceDB(connection=db, embedding=embeddings, table_name='my_knowledge_base')` —— LangChain 封装的 LanceDB 接口
- `vector_db.similarity_search(query, k=3)` —— 核心操作：把问题转成向量 → 在数据库中找最相似的 3 个文档片段 → 返回
- `doc.page_content` —— 文档片段的文本内容
