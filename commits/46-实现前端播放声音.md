## 一、这次提交做了什么

前端接收 SSE 流中的 Base64 音频数据，用 **MSE（Media Source Extension）** 实时解码播放——AI 说一个字就能听到声音。同时在关闭对话框或切换输入模式时停止播放。（什么是MSE？Media Source Extensions，浏览器的一套API，让你可以用JavaScript动态构造媒体流，而不是直接给一个完整的MP3文件URL。普通的`<audio src="song.mp3">`需要等整个文件下载完才能播；MSE的做法是：你创建一个空的"媒体源"（MediaSource），往里面一小块一小块地"喂"音频数据（通过SourceBuffer），浏览器边收边解码边播放。就像水池和水龙头——传统方式是给你一桶水你喝完，MSE是给你接了一根水管，水（音频数据）持续流进来，你边接边喝。MSE在YouTube、Netflix等视频网站被广泛使用，是实现低延迟流媒体播放的关键技术。在这个项目中，每收到一个SSE音频块（约100ms的MP3片段），就立刻通过MSE塞给浏览器播放，实现AI说话和声音几乎同步的效果）

#### 新增变量（音频播放器状态）

```javascript
let mediaSource = null;
let sourceBuffer = null;
let audioPlayer = new Audio(); // 全局播放器实例
let audioQueue = [];           // 待写入 Buffer 的二进制队列
let isUpdating = false;        // Buffer 是否正在写入
```

- `mediaSource` —— MSE 的媒体源对象。每个流一个实例
- `sourceBuffer` —— MSE 的缓冲区。MP3 数据通过它喂给 `<audio>` 元素
- `audioPlayer = new Audio()` —— 隐式 `<audio>` 元素。不需要插入 DOM，直接 JS 控制播放
- `audioQueue = []` —— 音频块的等待队列。收到 Base64 数据→解码→入队→串行写入 SourceBuffer
- `isUpdating = false` —— **互斥锁**。`sourceBuffer.appendBuffer()` 是异步方法，同一时间只能有一个 `appendBuffer` 在执行。`isUpdating` 防止并发写入。（为什么需要这个锁？SourceBuffer的工作方式是"写入一块数据→浏览器忙一会儿解码→解码完成触发updateend事件→才能写下一块"。如果在前一块还没解码完时就写新数据，浏览器会直接报错。`isUpdating`就是一个门禁——值为true表示"正在写入，请等待"，新来的音频数据先放入`audioQueue`队列排队；当`updateend`事件触发时设为false，然后从队列里取下一个音频块写入。这样保证了每次只有一个appendBuffer在运行，不会冲突。就像银行柜台——柜员正在服务一个客户时，新来的客户先拿号排队（audioQueue），柜员叫号（updateend）才服务下一个）

#### `initAudioStream()`——初始化 MSE 播放器

```javascript
const initAudioStream = () => {
    audioPlayer.pause();
    audioQueue = [];
    isUpdating = false;

    mediaSource = new MediaSource();
    audioPlayer.src = URL.createObjectURL(mediaSource);

    mediaSource.addEventListener('sourceopen', () => {
        try {
            sourceBuffer = mediaSource.addSourceBuffer('audio/mpeg');
            sourceBuffer.addEventListener('updateend', () => {
                isUpdating = false;
                processQueue();
            });
        } catch (e) {
            console.error("MSE AddSourceBuffer Error:", e);
        }
    });

    audioPlayer.play().catch(e => console.error("等待用户交互以播放音频"));
};
```

**逐行讲解**：

- `audioPlayer.pause()` —— 暂停上一轮播放（如果有）
- `audioQueue = []` —— 清空上一轮的音频队列
- `mediaSource = new MediaSource()` —— 创建媒体源对象。`MediaSource` 是 MSE API 的核心，代表一个"虚拟的媒体文件"
- `audioPlayer.src = URL.createObjectURL(mediaSource)` —— 把 MediaSource 变为 Blob URL 赋值给 Audio 元素。浏览器认为在播放一个"动态生成的文件"
- `mediaSource.addEventListener('sourceopen', ...)` —— MediaSource 打开时触发。在此之前 `sourceBuffer` 不存在，不能写入
- `mediaSource.addSourceBuffer('audio/mpeg')` —— 创建 MP3 格式的 SourceBuffer。MIME 类型 `audio/mpeg` 对应 MP3
- `sourceBuffer.addEventListener('updateend', ...)` —— **关键事件**。`appendBuffer()` 完成后触发。此时 `isUpdating = false`，然后调用 `processQueue()` 处理队列中下一个音频块
- `audioPlayer.play().catch(...)` —— 开始播放。`.catch()` 捕获自动播放被浏览器阻止的错误（某些浏览器要求用户先交互才能播放音频）

#### `processQueue()`——串行消费音频队列

```javascript
const processQueue = () => {
    if (isUpdating || audioQueue.length === 0 || !sourceBuffer || sourceBuffer.updating) {
        return;
    }

    isUpdating = true;
    const chunk = audioQueue.shift();
    try {
        sourceBuffer.appendBuffer(chunk);
    } catch (e) {
        console.error("SourceBuffer Append Error:", e);
        isUpdating = false;
    }
};
```

**逐行讲解**：

- `if (isUpdating || audioQueue.length === 0 || !sourceBuffer || sourceBuffer.updating)` —— 四个条件任一满足就 return：
  - `isUpdating` —— 正在写入中
  - `audioQueue.length === 0` —— 队列为空，没有数据
  - `!sourceBuffer` —— SourceBuffer 还没创建
  - `sourceBuffer.updating` —— SourceBuffer 自身正在更新（双重保险）
- `const chunk = audioQueue.shift()` —— 从队列头部取出一个音频块（FIFO 先进先出）
- `sourceBuffer.appendBuffer(chunk)` —— **核心操作**。把二进制 MP3 数据写入 SourceBuffer，浏览器自动解码并送入 Audio 管道播放

#### `stopAudio()`——停止播放并清理

```javascript
const stopAudio = () => {
    audioPlayer.pause();
    audioQueue = [];
    isUpdating = false;

    if (mediaSource) {
        if (mediaSource.readyState === 'open') {
            try {
                mediaSource.endOfStream();
            } catch (e) {
            }
        }
        mediaSource = null;
    }

    if (audioPlayer.src) {
        URL.revokeObjectURL(audioPlayer.src);
        audioPlayer.src = '';
    }
};
```

- `audioPlayer.pause()` —— 停止播放
- `mediaSource.readyState === 'open'` —— 检查 MediaSource 是否仍处于 open 状态。如果是，调用 `endOfStream()` 通知"不会再有更多数据了"
- `mediaSource.endOfStream()` —— 结束媒体流。SourceBuffer 写完所有数据后调用，浏览器知道流结束了
- `URL.revokeObjectURL(audioPlayer.src)` —— 释放 Blob URL 占用的内存。`createObjectURL` 创建的 URL 不会自动回收，必须手动释放
- `mediaSource = null` —— 释放引用

#### `handleAudioChunk()`——接收并解码 Base64 音频

```javascript
const handleAudioChunk = (base64Data) => {
    try {
        const binaryString = atob(base64Data);
        const len = binaryString.length;
        const bytes = new Uint8Array(len);
        for (let i = 0; i < len; i++) {
            bytes[i] = binaryString.charCodeAt(i);
        }

        audioQueue.push(bytes);
        processQueue();
    } catch (e) {
        console.error("Base64 Decode Error:", e);
    }
};
```

- `atob(base64Data)` —— **a**scii **to** **b**inary。浏览器内置函数，把 Base64 字符串解码为原始二进制字符串
- `new Uint8Array(len)` —— 创建指定长度的无符号字节数组（每个元素 0-255）
- `binaryString.charCodeAt(i)` —— 取二进制字符串第 i 个字符的 Unicode 码点（0-255 范围内）。逐字符填充到字节数组
- `audioQueue.push(bytes)` —— 入队
- `processQueue()` —— 触发消费

### 2.2 `chat.py`——后端加反缓冲头

```diff
         response['Cache-Control'] = 'no-cache'
+        response['X-Accel-Buffering'] = 'no'
```

`X-Accel-Buffering: no` —— 告诉 Nginx **不要缓冲**此响应。Nginx 默认缓冲代理响应（等数据凑够一定量再一起发给客户端）。对 SSE 流来说缓冲会导致前端收不到实时数据——AI 说了好几秒前端才一次性收到。加这个头禁用缓冲。
