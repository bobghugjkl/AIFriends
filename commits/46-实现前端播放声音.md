## 一、这次提交做了什么

前端接收 SSE 流中的 Base64 音频数据，用 **MSE（Media Source Extension）** 实时解码播放——AI 说一个字就能听到一个字的声音（边收边播）。

---

## 二、MSE 音频流播放

```javascript
let mediaSource = null;
let sourceBuffer = null;
let audioPlayer = new Audio();
let audioQueue = [];           // 待写入的二进制队列
let isUpdating = false;        // 防止并发写入

const initAudioStream = () => {
    mediaSource = new MediaSource();
    audioPlayer.src = URL.createObjectURL(mediaSource);

    mediaSource.addEventListener('sourceopen', () => {
        sourceBuffer = mediaSource.addSourceBuffer('audio/mpeg');
        sourceBuffer.addEventListener('updateend', () => {
            isUpdating = false;
            processQueue();    // Buffer空闲 → 处理队列中的下一个
        });
    });

    audioPlayer.play();
};
```

**MSE 是什么**：浏览器原生的 API，允许 JavaScript **动态构造媒体流**。不用此 API 的话，必须等整个音频文件下载完才能播放。MSE 让你边下载片段边播放——和直播技术原理一样。

核心流程：
1. 收到 Base64 音频 → Base64 解码 → `Uint8Array` → 放入 `audioQueue`
2. `processQueue()` 从队列取出一个 → `sourceBuffer.appendBuffer(chunk)` → 浏览器播放
3. `sourceBuffer` 在写入时不能同时写入新数据 → `isUpdating` 标志位 + `updateend` 事件 → 空闲后处理下一个

```javascript
const handleAudioChunk = (base64Data) => {
    const binaryString = atob(base64Data);       // Base64 → 二进制字符串
    const len = binaryString.length;
    const bytes = new Uint8Array(len);
    for (let i = 0; i < len; i++) {
        bytes[i] = binaryString.charCodeAt(i);   // 每个字符 → 字节值
    }
    audioQueue.push(bytes);
    processQueue();
};
```

**`atob`**：浏览器内置函数，**a**scii **to** **b**inary——解码 Base64 字符串。

**`X-Accel-Buffering: no`**：Django 响应头，告诉 Nginx **不要缓冲**响应。否则 Nginx 会等全部数据都有了再推给前端，流式就失效了。

## 四、总结

| 新增/修改 | 说明 |
|-----------|------|
| MSE 音频流 | 边收 Base64 音频边播放，不等完整文件 |
| `audioQueue` + `processQueue` | 队列 + 串行写入，防止 Buffer 并发写冲突 |
| `X-Accel-Buffering: no` | 禁止 Nginx 代理缓冲 |
| VAD 路径修复 | 部署后从 Django 加载模型文件 |
