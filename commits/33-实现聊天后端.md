## 三、`ChatGraph`——LangGraph 工作流

**文件**：`backend/web/views/friend/message/chat/graph.py`（新文件）

```python
import os
from typing import TypedDict, Annotated, Sequence

from langchain_core.messages import BaseMessage
from langchain_openai import ChatOpenAI
from langgraph.constants import START, END
from langgraph.graph import add_messages, StateGraph


class ChatGraph:
    @staticmethod
    def create_app():
        llm = ChatOpenAI(
            model='deepseek-v3.2',
            openai_api_key=os.getenv('API_KEY'),
            openai_api_base=os.getenv('API_BASE'),
        )

        class AgentState(TypedDict):
            messages: Annotated[Sequence[BaseMessage], add_messages]

        def model_call(state: AgentState) -> AgentState:
            res = llm.invoke(state['messages'])
            return {'messages': [res]}

        graph = StateGraph(AgentState)
        graph.add_node('agent', model_call)
        graph.add_edge(START, 'agent')
        graph.add_edge('agent', END)

        return graph.compile()
```

**逐段讲解用大白话**：

### 这些库是什么

- **LangChain**：一个 Python 框架，封装了调用各种大模型 API 的标准接口。不管是 OpenAI、DeepSeek、Claude，都可以用同一套代码调用
- **LangGraph**：LangChain 生态中的工作流引擎。把 AI 调用、工具调用、条件判断等节点组成一个有向图（Graph）

### 代码解释

- `llm = ChatOpenAI(model='deepseek-v3.2', ...)` —— 创建一个 LLM（大语言模型）客户端。虽然用的是 `ChatOpenAI` 类（OpenAI 兼容接口），实际调的是 DeepSeek（`API_BASE` 指向 DeepSeek 的服务器地址）。这体现了 LangChain 的抽象能力——只要模型实现了 OpenAI 兼容接口，就能用同一套代码

- `openai_api_key=os.getenv('API_KEY')` —— 从环境变量读取 API 密钥。`.env` 文件里定义了 `API_KEY=sk-xxx`，`load_dotenv()` 加载后 `os.getenv('API_KEY')` 就能读到

- `class AgentState(TypedDict)` —— 定义这个图的"状态"。`TypedDict` 是 Python 的类型提示，声明这个字典有一个 `messages` 键，值是一个消息列表。`Annotated[..., add_messages]` 的含义：当多个节点都返回 `{'messages': [...]}` 时，用 `add_messages` 函数**合并**消息列表（追加而不是覆盖）

- `def model_call(state) -> AgentState:` —— 这是一个**节点函数**。接收当前状态（消息列表），调用 LLM，返回新消息。LangGraph 会在每个节点执行后更新状态

- `llm.invoke(state['messages'])` —— 把整个消息列表发给 AI。`invoke` 是同步调用（阻塞等待 AI 返回完整回复）

- `graph = StateGraph(AgentState)` —— 创建一个以 `AgentState` 为状态的图

- `graph.add_node('agent', model_call)` —— 向图添加一个名为 `'agent'` 的节点，绑定的处理函数是 `model_call`

- `graph.add_edge(START, 'agent')` —— 从开始节点连到 agent 节点（进入图时先执行 agent）

- `graph.add_edge('agent', END)` —— agent 执行完后结束（没有循环）

- `graph.compile()` —— 编译图为可执行的工作流

**目前的工作流就是最简单的**：START → agent（调用 LLM） → END。后续提交会加入工具调用、条件路由等复杂逻辑。

## 四、`MessageChatView`——聊天 API

**文件**：`backend/web/views/friend/message/chat/chat.py`（新文件）

```python
class MessageChatView(APIView):
    permission_classes = [IsAuthenticated]
    def post(self, request):
        friend_id = request.data['friend_id']
        message = request.data['message'].strip()
        if not message:
            return Response({'result': '消息不能为空'})

        friends = Friend.objects.filter(pk=friend_id, me__user=request.user)
        if not friends.exists():
            return Response({'result': '好友不存在'})
        friend = friends.first()

        app = ChatGraph.create_app()            # 创建 LangGraph 工作流
        inputs = {
            'messages': [HumanMessage(message)]  # 用户消息包装为 HumanMessage
        }
        res = app.invoke(inputs)                 # 同步调用 AI
        print(res['messages'][-1].content)       # 终端打印 AI 回复（调试用）

        return Response({'result': 'success'})   # BUG: 没返回 AI 回复内容！
```

**讲解**：

- `HumanMessage(message)` —— LangChain 的消息类型。把字符串包装为 `HumanMessage` 对象，LangChain 会根据消息类型知道这是用户说的
- `app.invoke(inputs)` —— 同步执行 LangGraph 工作流。整个过程是同步的（阻塞），AI 回复完才返回给前端
- `res['messages'][-1].content` —— `res['messages']` 是完整消息列表（包含初始的用户消息和 AI 的回复消息），`[-1]` 取最后一条（AI 回复），`.content` 取其文本内容
- **`print(...)` + `return Response({'result': 'success'})` —— 明显的未完成代码**：AI 回复只在终端打印了，前端收到的只有 `{'result': 'success'}`，看不到 AI 说了什么。后续提交会改成流式返回给前端
