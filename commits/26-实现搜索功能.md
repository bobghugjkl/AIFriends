## 二、后端：搜索查询

**文件**：`backend/web/views/homepage/index.py`

```python
from django.db.models import Q

search_query = request.query_params.get('search_query', '').strip()
if search_query:
    queryset = Character.objects.filter(
        Q(name__icontains=search_query) | Q(profile__icontains=search_query)
    )
else:
    queryset = Character.objects.all()
characters_raw = queryset.order_by('-id')[items_count: items_count + 20]
```

**逐行讲解**：

- `Q(name__icontains=search_query) | Q(profile__icontains=search_query)` —— Django ORM 的**Q 对象**，用于构造复杂的 OR 查询。普通 `.filter()` 只能做 AND，`Q` 能做 `|`（OR）和 `~`（NOT）

- `icontains` —— **i** = case **i**nsensitive（不区分大小写），**contains** = 包含。即**模糊匹配**——数据库层面的 `LIKE '%keyword%'` 操作。SQLite 默认不区分大小写，PostgreSQL 用 `ILIKE`

- `|` —— Python 的位或运算符，在 Q 对象中表示 OR。`name__icontains OR profile__icontains` ——名字或角色介绍中包含关键词

- `search_query = request.query_params.get('search_query', '')` —— 用 `.get()` 取可选参数，访问 `/api/homepage/index/` 不传搜索词时，`search_query` 为 `''`，走 else 分支返回全部

**同时修正了分页**：`items_count + 1` → `items_count + 20`（上上提交遗留的调试代码）

## 三、前端：搜索流程

### 3.1 导航栏——搜索表单

```javascript
const searchQuery = ref('')

watch(() => route.query.q, newQ => {
  searchQuery.value = newQ || ''
})

function handleSearch() {
  router.push({
    name: 'homepage-index',
    query: { q: searchQuery.value.trim() }
  })
}
```

- 搜索框改为 `<form @submit.prevent="handleSearch">` —— 按 Enter 或点搜索按钮 → 调用 `handleSearch()`
- `router.push({name: 'homepage-index', query: {q: '关键词'}})` —— 跳转到首页，URL 变成 `/?q=关键词`。不传搜索词时 `q` 为空字符串，Router 自动去掉 query 参数
- `watch(() => route.query.q, ...)` —— 监听 URL 中的 `?q=` 参数变化，同步到输入框。这样用户输入后 URL 变了，输入框也保持显示同样的文字

### 3.2 首页——响应搜索词变化

```javascript
function reset() {
  characters.value = []
  isLoading.value = false
  hasCharacters.value = true
  loadMore()
}

watch(() => route.query.q, newQ => {
  reset()
})
```

当 `?q=` 变化时，**清空角色列表** → 重置分页状态 → 重新加载第一页。

**完整搜索链路**：
1. 用户在导航栏搜索框输入"猫娘" → 点搜索
2. `handleSearch()` → `router.push({query: {q: '猫娘'}})` → URL 变成 `/?q=猫娘`
3. 首页 `watch(query.q)` 触发 → `reset()` → `loadMore()` → `api.get('/api/homepage/index/', {params: {search_query: '猫娘'}})`
4. 后端 `Q(name__icontains='猫娘') | Q(profile__icontains='猫娘')` → 返回匹配结果
5. 首页渲染过滤后的角色卡片

**为什么用 URL query 而不是直接传参数**：把搜索词放在 URL 里，用户可以直接复制 URL 分享搜索结果。这也是 SPA 的一种"状态保持"手段。
